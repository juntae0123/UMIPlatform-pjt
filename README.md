### 현재 데이터셋이 학습에 부적합한 이유

`datasets/sim_pick_v0` 의 17 에피소드는 **포맷이 왕복한다는 증명** 용도다. 학습에 쓰면 안 된다.

1. **스크립트 시연이다.** 개루프 스크립트 궤적이라 다양성이 없다. 모델이 궤적 하나를 외운다
2. **예전 설정으로 기록됐다.** `lift_height_m` 12cm 시절인데 그 값은 도달 불가능해서
   궤적 마지막 구간에 관절한계에 걸린 자세가 들어 있다 (현재 8cm)
3. **계약이 미확정이다.** 아래 §9 의 결정 3건이 남아 있다

## 2. 반복해서 틀리는 지점

**평가 지표는 롤아웃 성공률이다. validation loss 가 아니다.**
모방학습에서 val loss 와 실제 성공률의 상관은 약하다. 손실은 정답 궤적과의 유사도를 재는데,
로봇은 다른 경로로도 성공하고 손실이 낮아도 오차 누적으로 실패한다. val loss 를 목표로
삼으면 지표는 좋아지는데 로봇은 계속 실패하는 상태에 빠진다.
**val loss 는 "학습이 망가지지 않았나" 확인용으로만 쓴다.**

**게이트 기준은 결과를 보기 전에 확정한다.** 기준은 `eval/rollout.py` 의 `GATES` 에 코드로
박혀 있다. 결과를 보고 고치면 판정이 아니라 사후 합리화다.

**baseline 없이 고급 모델로 넘어가지 않는다.** BC 성능을 재기 전에 ACT/Diffusion 을 돌리면,
성능이 나와도 이유를 설명 못 하고 안 나와도 원인(데이터 vs 모델)을 좁힐 수 없다.

**이미지-액션 타임스탬프 동기화를 수집 전에 계측한다.** 어긋나면 모델이 "과거 화면 보고
미래 행동"을 학습한다. 학습 손실은 잘 떨어지고 시뮬 성공률도 나오는데 실물에서만 실패해서,
이 프로젝트에서 원인 추적이 가장 어려운 실패 형태다.

**환경은 다양하게, 시연 방식은 동일하게.** 물체 위치·조명·배경은 다양할수록 좋지만,
접근 궤적·속도·그립 위치가 매번 다르면 그것은 다양성이 아니라 노이즈다.

**단계식으로 수집한다.** 20개 → 검증 → 프로토콜 확정 → 100개 → 게이트 → 나머지.
한 번에 몰아 찍고 나중에 문제를 발견하면 전량 폐기다.

**사람 손 궤적을 로봇이 재현하지 못할 수 있다.** 사람 손목은 자유롭게 꺾이지만 로봇은
관절 한계와 특이점이 있다. 그래서 **수집 착수 전에** 실행가능성 검사 도구가 필요하고,
그것이 `tools/reach_scan.py` 다.

**시뮬 성공률은 최종 지표가 아니다.** 시뮬 90% 가 실물 90% 를 보장하지 않는다.

### 확신도 표기

🟢 실행·로그 확인 / 🔵 문서·공개자료 / 🟡 설계 판단만.
미실행 코드와 미측정 수치는 **"미검증"** 을 명시한다. 모든 수치에 측정 조건을 병기한다.

## 3. 하드웨어 (실측 확인됨)

로봇: **SO-101** (5자유도 + 그리퍼), 리더-팔로워 구조.
리더 암을 손으로 움직이면 그것이 곧 시연 데이터다 — 별도 글러브가 필요 없다.

| | |
|---|---|
| 총질량 | 0.632 kg |
| 도달 범위 | 대략 반경 0.3 m |
| 그리퍼 닫힘 시 손가락 간격 | 약 1.7 cm → **대상물 1.5~2.5 cm** |

### 관절 범위 [rad]

`configs/so101.yaml` 이 정본이고, 값은 공식 MJCF 에서 그대로 가져왔다.
씬을 만들 때마다 MJCF 와 대조 검사한다 (`verify_against_config`, 불일치 0건).

| index | 관절 | min | max |
|---|---|---|---|
| 0 | shoulder_pan | -1.920 | 1.920 |
| 1 | shoulder_lift | -1.745 | 1.745 |
| 2 | elbow_flex | -1.690 | 1.690 |
| 3 | wrist_flex | -1.658 | 1.658 |
| 4 | wrist_roll | -2.744 | 2.841 |
| 5 | gripper | -0.175 | 1.745 (-0.175 = 닫힘) |

⚠️ **로봇팔은 변형 예정이다.** 하드웨어 의존 값은 `configs/` 로 분리하고
**코드에 하드코딩하지 않는다.**

⚠️ 5자유도 + 그리퍼는 위치(3) + 접근축(2) = **정확히 5개 구속**이다.
6자유도 완전 자세 제어는 불가능하다. IK 는 위치와 접근축만 맞춘다.

⚠️ MuJoCo 는 메시를 **볼록껍질**로 충돌시킨다. 두 갈래 그리퍼의 껍질이 턱 사이 공간을
메워서, 공식 MJCF 그대로는 완전히 벌려도 2cm 큐브가 턱에 들어가지 않는다.
`configs/so101.yaml` 의 `gripper_pads` 로 **로드 시점에 접촉 패드를 주입**해서 푼다.
공식 MJCF 는 수정하지 않는다 (업데이트 시 교체만).

## 4. 데이터 규격 (계약)

```
관측  image             (3, 224, 224) uint8, CHW, 카메라 2대
      state             (6,) float32, [-1, 1]
      state_timestamp   float64, 초
행동  action            (6,) float32, [-1, 1]   목표 관절각 5 + 그리퍼
      action_timestamp  float64, 초
주기  30 Hz

관절 순서 (변경 금지 — 바꾸면 수집 데이터 전부 무효)
  0 shoulder_pan   1 shoulder_lift   2 elbow_flex
  3 wrist_flex     4 wrist_roll      5 gripper

정규화  x_norm = 2 * (x_rad - lo) / (hi - lo) - 1     # lo, hi = configs 의 관절범위
        6축 전부 동일 규칙. 그리퍼를 특별 취급하지 않는다
```

저장 형식: 에피소드당 `.npz`(배열) + `.json`(메타), 데이터셋 루트에 `dataset.json`.

검증기(`contract/episode.py` 의 `validate`)가 보는 것:
dtype · shape · 값 범위 · 타임스탬프 단조증가 · state/action 타임스탬프 오차 10ms 이내 ·
제어주기 흔들림 20% 이내 · 계약 버전 일치.
**첫 위반에서 멈추지 않고 위반 목록 전체를 반환한다.**

⚠️ **이 규격이 바뀌면 수집한 데이터가 전부 무효가 된다.** 변경 제안에는 양 트랙 합의와
D-AI 기록이 필요하다. 그래서 `contract/` 를 별도 디렉터리로 떼어 뒀다.

## 5. 실행 환경과 컴퓨팅 자원

| | |
|---|---|
| 실행 환경 | ROS2 Humble, MoveIt (SO-101 URDF → IK) |
| 추론 디바이스 | Jetson. **VLM + 정책 합쳐 8GB 제약** (이슈 42 에서 검증 예정, 미검증) |
| 안전 | Safety Controller 별도 노드 (리밋·비상정지) |
| 백엔드 | 학습 대기 큐, 배포 API(ckpt·VLM 버전기록), 관제 수집 API |
| 프론트 | 로봇 등록(URDF)·스킬·배포 관리 UI, 상태·진행 관제 화면 |

| 자원 | 상태 |
|---|---|
| RTX 4070 노트북 / RTX 5070 데스크탑 | 사용 중 |
| H200 서버 | **신청했으나 미할당.** 할당되면 학습·파인튜닝 이관 |

⚠️ **Jetson 8GB 제약 때문에 VLM 은 반드시 경량 스코프를 유지해야 한다.**
VLM 을 키우면 정책 모델이 올라갈 자리가 없어진다.

⚠️ **Isaac Sim 은 RT 코어가 필요해서 H200 에서 렌더링할 수 없다.** 로컬 RTX 에서만 돈다.
주력 시뮬레이터는 **MuJoCo** 다 — H200 을 포함해 어디서든 헤드리스 렌더링이 된다.
Isaac 을 시도하려면 `sim/isaac/` 에 `sim/base.py` 의 `RobotEnv` 를 구현하면 되고,
그 디렉터리의 `__init__.py` 에 착수 전 확인할 제약을 적어 뒀다.

### 트랙 경계

```
track_a/  →  contract/  ←  sim/ policy/ eval/ data/ vlm/ tracking/
 트랙 A       유일한 접점              트랙 B
```

- **트랙 B 는 `track_a/` 를 임포트하지 않는다.** 계약을 만족하는 에피소드만 보고,
  그것이 어떻게 만들어졌는지 알 필요가 없다
- **트랙 A 는 `sim/` `policy/` `eval/` 을 임포트하지 않는다.** 필요한 것은 `contract/` 다
- 이 경계를 넘는 임포트가 생기면 접점이 둘이 된 것이다. D-AI 기록이 필요하다

⚠️ **비대칭이다.** 트랙 B 코드는 `track_b/` 로 묶여 있지 않고 기능별로 흩어져 있다.

`contract/` 는 두 트랙의 유일한 접점이고, 바뀌면 이미 수집한 에피소드가 전부 무효가 된다.

**1. 관절 정규화 규칙** (제안) — 6축 동일 선형 매핑, 그리퍼 특별 취급 없음.

매핑이 URDF/MJCF 에 반영되지 않았다"고 경고한다. rad 기반 통일 규칙으로 두면 그 불일치를

시뮬에서는 오차가 구조적으로 0 이라 무의미해 보이지만, 실물에서 S15P21A103-30 이 이 오차를
계측해야 하고 **필드가 없으면 계측 자체가 불가능하다.**

**3. 정규화 범위 초과값 처리** (**제안 없음 — 결정 필요**)
실측: 18건 수집 중 1건에서 정규화 state 최댓값이 **1.0062** 로 계약 `[-1, 1]` 을 벗어나

| 클립한다 | 정보 손실. 대신 계약이 단순하고 모델 입력 가정이 안전 |


이슈 제목: `<이슈키> <타입>: <무엇을 했는가>` — 이슈 키가 맨 앞이어야 인식된다.
완료 기준은 반드시 판정 가능하게 쓴다. "잘 동작한다" ❌ → "타임스탬프 오차 10ms 이내" ✅

`ai` 브랜치 아래에 트랙별 중간 브랜치를 두지 않는다 — 두 트랙의 접점이 데이터 포맷
하나뿐이라 충돌이 드물고, 중간 계층은 머지 비용만 늘린다. 충돌이 잦아지면 그때
`ai/track-a`, `ai/track-b` 분리를 검토한다.

### 기록

| 무엇이 생기면 | 어디에 |
|---|---|
| 결정이 내려지면 | `DECISIONS.md` — `D-AI-{n}`, 작성자와 **되돌릴 조건** 포함 |
| 실험·계측 결과 | `docs/MEASURE_*` — 측정 조건 병기 |
| 트러블슈팅 종료 | `docs/TS_*` — "고쳤다"가 아니라 **"어떻게 좁혔나"** 구조 |
| 미검증 항목 | `LIMITS.md` |
| 기각된 아이디어 | `REJECTED.md` |

`D-AI-{n}` 번호는 두 트랙 공용이다. 항목마다 작성자를 명시한다.
한쪽 트랙의 결정이 다른 트랙에 영향을 주면 (특히 **데이터 포맷·좌표계·제어 주기**)
반드시 상대 트랙 확인을 거친다. 상대 트랙 작업을 임의로 추정해서 판단하지 않는다.
