# SO-101 모방학습 — 시연으로 배우는 로봇팔

사람이 한 번 보여주면 로봇팔이 그 조작 작업을 배우는 시스템.
이 저장소는 그중 **학습·평가 파트(트랙 B)** 다.

```
사람 시연 ──> 데이터 계약 ──> 정책 학습 ──> 롤아웃 평가 ──> 배포
 (UMI 그리퍼)   (contract/)    (policy/)     (eval/)      (게이트 통과분만)
                                  ↑
                          시뮬 데이터·평가 harness (sim/)
```

SSAFY 특화 프로젝트 · 2인 AI 파트 중 학습·모델 담당 · 진행 중

## 이 저장소에서 가장 중요한 한 장면

```
학습 손실  0.00547  →  0.00517   (더 낮췄다)
롤아웃 성공률  0%   →     0%     (하나도 안 바뀌었다)
```

모방학습에서 손실과 성공률의 상관은 약하다. 손실은 시연 궤적과의 유사도를 재는데,
로봇은 다른 경로로도 성공하고 손실이 낮아도 오차가 누적돼 실패한다.
**그래서 이 프로젝트는 착수 시점에 "평가 지표는 롤아웃 성공률이다"를 규칙으로 박았고,**
2026-09-01 에 그 규칙이 실측으로 확인됐다. 독립 학습 2회에서 재현됐다.

손실만 봤다면 "학습 잘 되네" 하고 넘어갔을 상황이다.

### 그래서 원인을 어떻게 좁혔나

| 가설 | 판정 | 근거 |
|---|---|---|
| 계측기가 고장났다 | 배제 | 같은 실행에서 스크립트 정책이 95~100% |
| 전처리가 학습/추론에서 다르다 | 배제 | 두 경로 코드 대조 |
| 학습 무작위성 | 배제 | 독립 학습 2회 동일 결과 |
| 아무것도 배우지 못했다 | 배제 | 예측 행동 표준편차 / 정답 = 0.94~1.01 |
| 모드 평균 붕괴 | 배제 | 위와 같음 |
| 인식·일반화 실패 | 배제 | 물체 위치를 고정해도 0% (스크립트는 100%) |
| **절대 행동 표현의 정밀도 부족** | **원인** | 아래 |

```
관절             시연이 요구하는 이동량   정책의 예측 오차   오차 ÷ 이동량
shoulder_pan            0.0502°              0.5485°          10.9
wrist_roll              0.0059°              0.0744°          12.6
shoulder_lift           0.2778°              0.4502°           1.62
elbow_flex              0.3881°              0.5919°           1.53
wrist_flex              0.8564°              0.6404°           0.75
gripper                 1.5931°              0.4410°           0.28
```

**6개 관절 중 4개에서 예측 오차가 요구되는 이동량보다 크다.** 팔을 위치시키는 관절이
전부 여기 해당하고, 신호가 오차보다 큰 것은 그리퍼와 손목뿐이다. 그래서 이 정책은
**집게는 여닫지만 팔을 가져다 놓지 못한다.**

행동을 절대 관절각으로 예측하면 손실의 대부분이 "팔이 지금 어디 있나"로 채워지고,
실제로 움직임을 만드는 잔차 `action − state` 는 틀린 채 남는다. 대책은 델타 행동 →
관절별 손실 가중 → (그다음에야) 행동 청킹 순서다.

## 설계 원칙

**1. 게이트 기준은 결과를 보기 전에 코드에 박는다.**
`eval/rollout.py` 의 `GATES`, `eval/transfer.py`, `contract/skills.py` 전부 상수로 고정돼
있다. 결과를 보고 기준을 정하면 판정이 아니라 사후 합리화다.

**2. 계측기를 쓰기 전에 계측기를 검증한다.**
`tools/check_domain.py` 는 도메인 랜덤화가 실제로 무언가를 흔드는지 13항목으로 확인한다
(픽셀 평균 절대차까지 잰다). 조건 B 가 조용히 아무것도 안 흔들면 붕괴율은 0으로 나오고
결론은 "전이가 잘 된다"가 된다. 나올 수 있는 가장 비싼 오답이다.

**3. n 이 작으면 게이트를 판정할 수 없다 — 게이트가 아니라 n 을 올린다.**
n=20, p≈0.8 의 95% 신뢰구간 반폭이 약 ±18%p 로 게이트 폭(20%p)과 같다.
같은 정책이 시드 블록에 따라 95%와 70%로 갈렸다.

**4. 같은 데이터·설정으로도 학습 실행 간 성공률이 25%p 갈린다.**
그래서 배포 게이트는 `n ≥ 100` 과 `runs ≥ 3`, 그리고 **신뢰구간 하한**까지 요구한다.

**5. 수치를 손으로 적지 않는다.**
아래 측정 수치 절은 `EXP_LOG.jsonl` 에서 자동 생성된다. 실험 1건 = 1줄, git 리비전과
설정 해시가 함께 기록된다. 손으로 적은 수치는 조용히 낡는다.

## 계측기 — 각각 무엇을 판정하는가

| 도구 | 답하는 질문 |
|---|---|
| `tools/eval_rollout.py` | 정책이 baseline 보다 의미 있게 나은가 (유일한 판정 지표) |
| `tools/diagnose_bc.py` | 손실이 낮은 이유가 학습인가, 태스크가 쉬운 함수로 근사되기 때문인가 |
| `tools/image_sensitivity.py` | 정책의 행동이 실제로 **보는 것**에 반응하는가 |
| `tools/success_map.py` | 정책이 작업공간의 **어디에서** 되는가 (구역을 외웠나, 전반적으로 부족한가) |
| `tools/check_domain.py` | 도메인 랜덤화가 실제로 흔드는가 (계측기 자체 검증) |
| `tools/measure_transfer.py` | 도메인이 바뀌면 정책이 얼마나 무너지는가 |
| `tools/grasp_check.py` | 물체가 얼마나 벗어나도 스크립트 파지가 되는가 |
| `tools/reach_scan.py` | 팔이 실제로 닿는 영역은 어디인가 |
| `tools/check_skills.py` | 이 스킬이 배포 가능한 상태인가 |
| `tools/record_rollout.py` | 실패가 **어떻게** 생겼는가 (화면 없는 서버에서 영상으로) |

`tools/diagnose_bc.py` 는 정책의 손실을 "가만히 있기(identity)"·"항상 평균 자세(mean)"와
같은 프레임에서 비교한다. 자명한 함수보다 뚜렷하게 낫지 않으면 그 손실은 태스크 수행
가능성에 대해 아무것도 말하지 않는다.

## 구조

```
contract/     데이터 계약. 두 트랙의 유일한 접점
  ids.py        스킬 식별자 등 공유 어휘
  episode.py    관측·행동·타임스탬프 규격 + 검증기
  skills.py     스킬 레지스트리, 배포 게이트, VLM 출력 파서
policy/       BC 정책, baseline 4종, 학습 루프
eval/         롤아웃 채점, 전이 붕괴율, 진단, 성공 위치 지도, 영상 기록
sim/
  base.py       시뮬레이터를 모르는 RobotEnv 프로토콜 (실물이 같은 표면을 만족한다)
  mujoco/       MuJoCo 백엔드. 공식 MJCF 는 수정하지 않고 로드 시점에 조립한다
data/         수집·검증·데이터셋
configs/      하드웨어 의존 값 단일 출처. 코드에 하드코딩 금지
tools/        진입점
docs/         MEASURE(계측) · TS(트러블슈팅) · DECISIONS(결정) · DEVLOG · KPT

LIMITS.md     미검증 항목 목록
REJECTED.md   기각한 아이디어와 되살릴 조건 ("안 만든 것도 결정")
```

`sim/base.py` 에 MuJoCo 임포트가 없는 것은 의도적이다. 실물 팔이든 다른 시뮬레이터든
같은 표면을 만족하면 정책 코드를 바꾸지 않는다. 이 교체 가능성은 시뮬레이터 없는 더미
환경으로 실제로 검증했다 (`tools/check_interface.py`).

## 실행

```bash
pip install mujoco==3.12.0 pyyaml torch numpy
export MUJOCO_GL=egl          # 헤드리스. 뷰어를 쓸 때는 이 변수를 지운다

python tools/reach_scan.py --log            # 작업공간 도달성
python tools/collect_sim.py --episodes 100 --skill-id pick_place \
       --out datasets/sim_pick_v2 --log     # 시뮬 시연 수집
python tools/verify_dataset.py datasets/sim_pick_v2 --log
python tools/train_bc.py --data datasets/sim_pick_v2 --device cuda --log
python tools/eval_rollout.py --episodes 100 --render \
       --policy-ckpt checkpoints/bc/bc_sim_pick_v2.pt --log
```

전 과정을 게이트와 함께 한 번에 돌리려면 `bash tools/run_transfer_study.sh 0 100`.
각 단계가 다음 단계의 게이트라, 실패하면 그럴듯한 하류 수치를 만드는 대신 멈춘다.

씬을 눈으로 보려면 `python tools/view.py`, 학습된 정책이 도는 것을 보려면
`python tools/view.py --policy bc --policy-ckpt <경로>`.
