# 외부 검토 요청 — 시뮬 BC 정책이 폐루프에서만 실패한다

이 문서는 다른 AI/사람에게 그대로 붙여 넣기 위한 자기완결 브리핑이다.
모든 수치는 `AI/EXP_LOG.jsonl` 에 git 리비전과 함께 기록된 실측이다.
확신도: 🟢 실행·로그 확인 / 🔵 문서·공개자료 / 🟡 설계 판단만

---

## 0. 당신에게 부탁하는 것

**질문 하나:** 전문가(스크립트 정책)가 84% 인 태스크에서, 그 전문가가 만든 시연
98편으로 학습한 행동복제(BC) 정책이 **9.3%** 다. 진단은 "폐루프 누적 오차"를
가리키는데, 우리가 놓친 더 싼 설명이나 더 정보량 높은 다음 실험이 있는가?

**답변 형식 요청**
1. 아래 §5 진단이 배제한 것과 배제하지 못한 것을 다시 정리해달라. 우리가 배제했다고
   착각한 항목이 있으면 그것부터
2. 우리의 다음 계획(DAgger)보다 정보량이 높은 실험이 있으면 그것과 이유
3. 각 제안에 **판정 방법**을 붙여달라. "해보면 좋다"가 아니라 "무엇을 측정하고
   어떤 값이면 기각인가"

**지켜야 할 규칙 — 이 프로젝트의 기존 결정이며 논의 대상이 아니다**
- 판정 지표는 **롤아웃 성공률**이다. validation loss 가 아니다. 실증됐다 🟢:
  val 0.00547 → 0.00517 로 낮췄는데 롤아웃은 0% 그대로였고 독립 학습 2회 재현됐다.
  더 나아가 설정을 가로지르면 **역방향**이다 (§4 표)
- **95% 구간이 겹치는 두 실행은 이 n 으로 구분되지 않는다.** 평균이 높다고 개선이
  아니다. 게이트를 옮기는 제안은 사후 합리화이므로 받지 않는다. n 을 올리는 제안은 받는다
- 미측정 값을 결과처럼 쓰지 않는다. 대책보다 **계측기**를 먼저 제안해달라
- 모든 수치에 측정 조건을 병기한다. 조건 없는 절대값 인용은 무의미하다

## 1. 시스템

목표는 사람 시연으로 로봇팔이 조작 태스크를 배우는 제품이고, 지금 단계는 **시뮬에서
학습 루프와 계측기를 완성**하는 것이다. 실물은 아직 없다. 시뮬 성공률은 최종 지표가
아니라 실제 sim2real 갭의 **하한**이다.

- 로봇: SO-101, **5자유도 + 그리퍼** (0.632kg, 도달 반경 약 0.3m)
- 시뮬: MuJoCo 3.12.0, EGL 헤드리스, 제어 30Hz, 렌더 결정론 확보 🟢 (MSAA off → 비트 동일)
- 태스크: 2cm 20g 큐브 top-down 픽앤플레이스. 물체 xy 무작위 ±50mm
- 성공 판정: 물체가 안착 높이에서 **5cm 이상** 상승
- 틱 제한: 200 (30Hz → 6.7초)
- GPU: Tesla V100 32GB ×10. **bf16 미지원**, FlashAttention-2 없음, NVLink 없음

### 데이터 계약 (정본 `AI/contract/episode.py`, `0.2.0-provisional`)

```
관측  image  (3,224,224) uint8 CHW × 카메라 2대 (front, wrist)
      state  (6,) float32  관절 5 + 그리퍼, [-1,1] 범위 정규화
행동  action (6,) float32  목표 관절 5 + 그리퍼, [-1,1]
주기  30Hz · 타임스탬프는 obs/action 따로 보관
```

### 모델

- BC MLP-ish, **1,307,974 파라미터**. 이미지 인코더 + state 결합 → action 회귀
- 손실 **L1**
- 행동 표현 `joint_delta_gripper_abs` (팔 5관절은 `action − state` 델타, 그리퍼는 절대) 🟢
  (v1 은 절대 관절각이었다. 전환 시점은 EXP_LOG 로 확인 가능)
- epochs 30, 학습 1회 1332초 (V100 1장, 44.4초/epoch)
- **판정에는 마지막 epoch 을 쓴다.** best-val 체크포인트가 더 좋다는 근거가 이
  프로젝트에는 없다

## 2. baseline 과 게이트 (결과 보기 전 코드에 확정)

n=100, 시드 3000~3099, 모든 정책이 **같은 시드** = 같은 물체 배치.

| 정책 | 성공률 | 무엇을 말하는가 |
|---|---|---|
| `hold` 리셋 자세 유지 | **0%** 🟢 | 진짜 하한선 |
| `zero` 모든 관절 범위 중앙 | **0%** 🟢 | 우연 성공률 |
| `replay` 기록 궤적 재생 | **0%** 🟢 | 이 태스크는 관측을 봐야 풀린다 (시각 정책이 필요하다) |
| `scripted` 물체 참값으로 계획 | **84.0%** 🟢 | 상한선. 특권정보 사용, 배포 불가 |

`scripted` 84.0% 는 **7회 연속 동일**하게 나왔다 🟢 — 계측기가 표류하지 않고,
시연자 통일 작업이 궤적을 바꾸지 않았다는 증거이기도 하다.

**배포 게이트: 성공률 > 20%** (`ROLLOUT_GATE = 0.20`), 평가 n≥100, 학습 3회 반복.
게이트는 착수 전에 못 박았고 옮기지 않는다.

**태스크가 요구하는 정밀도** 🟢 — 기록 궤적을 재생하면서 물체만 옮겼을 때:

| 물체 이동 | 성공 |
|---|---|
| ±5mm | 4/4 |
| ±10mm | 3/4 |
| ±15mm | 1/4 |
| ±50mm | 0/4 |

즉 파지에 필요한 정밀도는 **약 5mm** 다.

## 3. 무엇을 바꿨고 무슨 결과가 나왔나

전부 학습 3회 반복 × 롤아웃 100편 = 합산 n=300, 동일 평가 시드 블록.

| 데이터셋 | 바꾼 것 | per_run | 평균 | 95% 구간 |

| `sim_pick_v3` | 시연자 통일 (수집 141틱 vs 평가 165틱 갈라짐 해소) | 9% / 3% / 1% | **4.3%** | 2.5~7.3% |
| `sim_pick_v4` | `dwell_s 0.5` — 파지 직후 정지 구간 주입 | 0% / 0% / 0% | **0.0%** | 0.0~1.3% |
| `sim_pick_v5` | `dwell_s 0.0` 회귀 | 14% / 12% / 2% | **9.3%** | 6.5~13.2% |
| `v5 + aug σ2.0` | 학습 이미지에 가우시안 잡음 (val 은 그대로) | 12% / 5% / ? | 판정완료 | (아래) |

### 여기서 나온 결론 세 개

**(1) v2 이후 성공률이 올랐다는 증거가 없다** 🟢
v5 구간(6.5~13.2%)이 v2(3.6~8.9%)와 v3(2.5~7.3%) **둘 다와 겹친다.** 5일간의 수집
조건 변경이 이 구간 안에서 움직였을 뿐이다. 유일하게 확실히 다른 것은 v4 다.

**(2) dwell 기각 확정** 🟢
v4 구간(0~1.3%)이 v5 구간과 겹치지 않는다. 부작용이 실현됐다 — dwell 프레임은 팔
관절 델타가 전부 0 이라 스파이크 목표 비율이 오르고, L1 의 최적값이 0 이라 정책이
더 안 움직인다. 이 부작용은 착수 전에 config 주석에 적어뒀고 "판정은 롤아웃이 한다"고
명시했었다.

**(3) 이미지 증강 기각 확정** 🟢
seed0 12% + seed1 5% = 17/200. 남은 seed2 에 **0~33% 전 구간을 대입해도** v5 구간과
겹친다. 갈라지려면 seed2 가 34% 이상이어야 하고 관측된 단일 시드 최댓값은 14% 다.
예상이 아니라 가능한 값 전체를 대입한 결과다.
**부수 관측이 중요하다** — 교사강요 오차 비율은 0.175 → **0.1313 으로 개선**됐는데
폐루프는 **성공 → 실패로 뒤집혔다.**

### 그 밖에 바꾼 것

| 바꾼 것 | 결과 |
|---|---|
| epochs 20 → 30 | 같은 데이터·시드에서 **0/100 → 14/100** 🟢. 구간 안 겹침 |
| 렌더 MSAA off (`offsamples: 0`) | 렌더 비트 단위 재현 확보 🟢 |
| 들어올림 IK 를 도달가능성 게이트에서 제거 | 100개 중 **25개가 잘못 탈락**하고 있었다 🟢 |
| `closing_moment` 히스테리시스 (5틱 유지 + 진폭 하위 25%) | 계측기 버그였다. 판정 60틱 vs 실제 102틱 🟢 |

## 5. 진단 — 무엇이 배제됐나

### 5-1. 3단 추적 (`trace_execution`) 🟢 — 가장 결정적

같은 체크포인트, 같은 에피소드로 세 가지를 따로 본다.

| 절 | 무엇을 보는가 | 결과 |
|---|---|---|
| **A** | 기록된 행동을 그대로 재생 | **통과** (상승 5.139cm) |
| **B** | 교사강요 — 매 틱 참 상태를 주고 정책 출력만 비교 | **통과** (오차 비율 0.222) |
| **C** | 폐루프 — 정책 출력을 실제로 실행 | **실패** |

C 에서 상태 차이가 **t=1 부터 약 10틱마다 2배**로 벌어진다. 이미지 차이는
0.28 → 8.53 계조. **A 통과 · B 통과 · C 실패는 공변량 이동(covariate shift)의
교과서적 서명이다.**

### 5-2. 배제된 가설 🟢

| 가설 | 배제 근거 |
|---|---|
| 도달 범위 부족 | 물체가 중심 0~15mm 인 구간에서 정밀도가 **가장 좋은데**(5.8mm) 성공률 0%. 가장 쉬운 곳에서도 실패 |
| 데이터 밀도 부족 | 위와 같은 측정. 시연이 가장 조밀한 중심부가 0% |
| 정책이 이미지를 안 본다 | `image_sensitivity` 델타기준 비율 **0.740** ≥ 0.30 통과 |
| 정책 붕괴(mode collapse) | bc L1 **0.001620** vs identity 0.007543. 출력 std 비율 0.970~1.001 |
| 들어올림 구간 신호가 약하다 | 구간별 델타 비교에서 lift 신호가 다른 구간과 비슷 |
| 파지 정밀도 부족 | 그리퍼 명령 원시열: bc 는 틱 **102**에 xy **2.7mm** / 3d 9.4mm / 턱접촉 6 으로 **잡는다.** scripted 와 비슷하다. 그리고 **틱 200까지 얼어붙는다** |
| dwell 표본 부족 | v4 0/300, 구간 안 겹침 |
| 이미지 증강 | v6, 위 §3-(3) |

### 5-3. 상한선 자체의 실패 형태 🟢 (n=4 예비, n=300 재확인 예정)

`scripted` 의 16% 실패는 **접근·파지 실패가 아니다.** 닫는 순간 물체까지 4.2mm
(허용 5mm 안), 턱 접촉 8개, 물체 밀림 3.7mm — 잘 집었는데 **안 들린다.**
들어올림 IK 가 약한 지점이라는 별도 측정(100개 중 25개 탈락)과 같은 방향이다.
즉 천장 84% 를 90%대로 올릴 여지가 여기 있다.

## 6. 지금 최우선 설명 (🟡 — 반증 환영)

**이미지 민감도는 취약점이 아니라 교정 채널이다.**

작은 이미지 변화를 무시하는 정책은 궤적에서 벗어난 상태를 되돌릴 수 없다. 증강은
한 스텝 예측(B)을 좋게 만들면서 폐루프(C)를 나쁘게 했다 — 정책에게 **교정하지 말라고
가르친 것**으로 읽힌다. 문제는 정책이 교정을 못 하는 것이 아니라, 교정이 **틀린** 것이고,
틀린 이유는 분포 밖 상태를 학습한 적이 없기 때문이다.

**그래서 계획한 다음 수: DAgger** — 시뮬에 84% 전문가가 있으므로 라벨 비용이 0 에 가깝다.

### 그런데 착수 전에 막힌 것 하나 🟢

기존 `scripted` 는 리셋에서 계획을 한 번 세우고 **틱 번호로 재생하는 개루프**다.
`obs` 를 아예 읽지 않는다. DAgger 는 "**이** 상태에서 전문가라면?"을 물어야 하는데
개루프는 자기가 어디 있는지 모르니 답할 수 없다. 그래서 상태 피드백 전문가를 먼저
만들고, **라벨 한 장 모으기 전에** 게이트로 판정하기로 했다.

- **G0-a** 교란 없는 성공률 ≥ 80% 이고 개루프 84% 와 구간이 겹칠 것 (제작 검사)
- **G0-b** 초기 관절 배치를 흩었을 때 복구 성공률 ≥ 60% (**착수 판정**).
  못 넘으면 DAgger 를 시작하지 않는다 — 전문가가 못 돌아오면 가르칠 것이 없다

만드는 중 계측기가 우리 버그 두 개를 잡았다 🟢:
(1) lift 목표를 물체의 **현재** 위치에서 계산해서, 들고 있는 물체의 8.8cm 위를
영원히 쫓았다 (lift IK 22/22 실패). (2) 턱접촉·물체밀림을 **닫는 명령이 나간 틱**에
재서 전부 0 이었다.
그리고 이것도 나왔다 🟢: **위치 제어에서는 5틱짜리 명령 교란이 저절로 지워진다** —
개루프조차 점수가 안 변한다. 그래서 G0-b 는 초기 관절 배치를 흩는 조건으로 판정한다.

## 7. 후보로 남아 있는 것 (🟡 전부 미측정)

- **action chunking / ACT** — 한 스텝씩 회귀하면 스텝마다 오차가 쌓인다
- **행동 표현** — 현재도 델타지만, 스파이크 목표(정지 구간의 델타 0)가 L1 하에서
  중앙값 최적 0 을 만든다. 구간별로 표현을 달리하는 방안
- **n 을 300 → 900 으로** — 지금 구간 폭이 게이트 폭과 같은 자릿수라 조건 간 순위를
  잴 수 없다. 다만 순위가 정해져도 20% 게이트와는 무관하다

## 8. 재확인용 질문 목록 (당신이 우리에게 되물어야 할 것)

우리가 스스로 확인하지 못한 것을 숨기지 않는다. 아래는 답이 없거나 🟡 다.

1. `image_sensitivity` 의 "델타기준 비율 0.740" 이 정말 "정책이 이미지를 쓴다"의
   충분한 증거인가? 임계 0.30 은 우리가 정한 값이다
2. 교사강요(B) 오차 비율 0.222 가 "통과"인 기준은 어디서 왔는가
3. 시드 간 12%p 편차의 원인 — 초기화? 데이터 분할? 미측정
