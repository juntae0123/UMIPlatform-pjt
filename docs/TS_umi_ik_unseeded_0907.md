# TS — 도달 가능한 pose 에서 IK 가 못 푸는 0.17% 를 좁힌 과정 (2026-09-07)

- 이슈 S15P21A103-127 · 작성 김준태(트랙B) · 확신도 🟢
- 후속: `MEASURE_umi_roundtrip_0907.md` M8-a

## 증상

UMI 합성 raw 20편(1800스텝)을 계약으로 변환했을 때 3스텝이 폐기됐다.
폐기 이유는 `ik_not_converged`.

**이상한 점:** 입력은 유효한 관절 배치에서 FK 로 만든 것이라 **전부 도달 가능**하다.
못 풀릴 이유가 없어야 한다. 0.17% 는 작지만 실데이터에서 이 비율이 커지면
수용률의 주요 손실원이 된다.

## 먼저 내가 잘못 읽었다 — 진단기가 파이프라인과 달랐다

진단 스크립트를 처음 돌렸을 때 **11건**이 나왔다. 파이프라인은 3건이었다.

원인은 진단기 쪽이었다. 진단기가 `prev = sol.q_rad` 를 **무조건** 실행해서
실패한 해까지 다음 스텝의 시드로 넘겼다. `umi.convert.convert` 는 성공했을 때만
`q_prev` 를 갱신한다. 그 차이가 ep7 에서 나쁜 시드의 연쇄를 만들어 3건을 11건으로
불렸다.

**진단기가 파이프라인과 다르게 동작하면 진단기의 수치를 재는 것이다.**
시드 정책을 맞추자 3건으로 일치했다.

부수 소득: `convert()` 가 실패 시 시드를 갱신하지 않는 것이 **하중을 받는 설계**임이
드러났다. 갱신하면 실패 1건이 연쇄한다.

## 가설 두 개와 그것을 구분하는 계측

| | 가설 | 지지되면 보여야 하는 것 |
|---|---|---|
| H1 | **특이자세.** 구속 야코비안이 랭크를 잃어 감쇠 최소자승이 못 내려간다 | 실패 스텝의 최소 특이값이 성공 스텝보다 뚜렷하게 작다 |
| H2 | **시딩/분지.** 직전 해에서 출발해 다른 분지에 갇혔다 | `q_init` 을 참값으로 주면 수렴한다 |

두 계측이 서로를 배제한다 — H1 이면 참값 시딩으로도 못 풀고, H2 면 풀린다.

야코비안은 `solve_pose_ik` 가 쌓는 것과 같은 행렬로 계산했다. 위치 3행 +
`axis_weight=0.15` 로 가중한 축 3행, 열은 풀이가 움직이는 관절 `[0,1,2,3]`.

## 판정 🟢

```
σmin  성공 1797건  중앙 0.05054  5퍼센타일 0.02370  최소 0.02000
      실패    3건  중앙 0.02719  최대 0.02762  최소 0.02669
      성공 스텝 중 실패 최대 σmin 보다 작은 것: 242건 (13.47%)

참값 시딩  3/3 이 위치 0.0000mm · 축 0.0000도 로 수렴
```

- **H1 기각.** 실패의 최악 σmin(0.02762)보다 작은 성공 스텝이 13.47% 있다.
  특이자세라면 그 242건도 실패해야 한다
- **H2 지지.** 참값 시딩으로 3/3 이 완전 수렴

## 기전 — 실패는 전부 "시드 없는 풀이"였다

실패 3건은 **ep7 의 step 0·1·2 연속**이다.

```
step 0   q_init=None  → 원점(qpos=0)에서 풀이 → 실패 (위치 44.8mm, 축 10.3도)
step 1   실패했으므로 q_prev 갱신 안 됨 → 또 원점에서 풀이 → 실패
step 2   같음 → 실패
step 3   목표가 원점의 수렴 분지로 들어옴 → 성공, 이후 직전 해로 이어짐
```

즉 **step 0 이 유일하게 시드가 없는 스텝**이고, 거기서 실패하면 시드가 계속
없는 상태가 유지된다. 특정 자세의 문제가 아니라 **초기값의 문제**다.

## 조치 — 시드 없는 스텝에만 다중시작

`MujocoIK._seed_grid()` 로 결정적 시드 8개(원점, 중앙, 관절범위의 ±35/60/85%)를
두고, `q_init` 이 없을 때만 다중시작해 오차가 가장 작은 해를 쓴다.
허용오차 안에 들면 즉시 멈춘다.

**비용은 시드 없는 스텝만 낸다 — 보통 에피소드당 한 번이다.**
`solve_pose_ik` 는 고치지 않았다 (시뮬·정책 소유).
