## D-AI-17 · VLM 학습 데이터는 MuJoCo 렌더에서 생성한다

작성자: 김준태(트랙B) · 관련 이슈: S15P21A103-36, 112

**결정**
VLM 파인튜닝용 이미지·라벨은 MuJoCo 렌더에서 생성한다. 단 **파인튜닝에
착수하기 전에 M0(파인튜닝 없는 베이스 모델의 스킬 선택 정확도)를 먼저 잰다.**

| M0 정확도 (n=100, 5지선다, 우연 = 0.20) | 판정 |
|---|---|
| ≥ 0.90 | 파인튜닝 취소. 자원을 grounding 정확도로 돌린다 |
| 0.50 ~ 0.90 | LoRA 필요. 시뮬 렌더 데이터셋 진행 |
| < 0.50 | 모델 후보 재검토 |

**왜**
baseline 없이 LoRA 를 돌리면 성능이 나와도 파인튜닝 덕인지 사전학습 덕인지
가릴 수 없다. BC→ACT 규칙과 같은 논리다.

**되돌릴 조건**
실물 카메라 이미지로 M0 를 재측정했을 때 렌더 대비 정확도가 0.15 이상 떨어지면
렌더 데이터셋만으로는 부족하다는 뜻이므로 재판정한다.

**미검증**
렌더 이미지로 학습한 VLM 이 실사에서 동작하는지 (LIMITS L22).

## D-AI-18 · 시뮬 정책의 UMI 보조 활용 여부는 도메인 전이 붕괴율로 판정한다

작성자: 김준태(트랙B) · 관련 이슈: S15P21A103-65

**결정**
시뮬 활용을 네 갈래로 나누고, 판정이 필요한 것은 S3·S4 뿐이다.

| | 형태 | 상태 |
|---|---|---|
| S1 | UMI 궤적 실행가능성 검사 | 채택 (붕괴율과 무관) |
| S2 | 평가 harness | 채택 (붕괴율과 무관) |
| S3 | 시뮬 사전학습 → UMI 데이터 파인튜닝 | **붕괴율로 판정** |
| S4 | 시뮬+실물 혼합 학습 | **붕괴율로 판정** |

`붕괴율 = 1 − (조건B 성공률 / 조건A 성공률)`

| 붕괴율 | 판정 |
|---|---|
| ≤ 0.30 | S3 시도 |
| 0.30 ~ 0.70 | 도메인 랜덤화 켜고 재수집·재학습 후 재판정 |
| ≥ 0.70 | S3/S4 기각. 자원은 UMI 실데이터로 |

전제 게이트: 조건 A 성공률 ≥ 20%. 못 넘으면 붕괴율을 산출하지 않는다
(분모가 작아 나눗셈이 의미를 잃는다).

**왜**
진짜 질문("시뮬 학습이 실물에 도움이 되는가")은 실물이 있어야 답할 수 있고
실물은 4주 뒤다. 그 안에 든 약한 질문은 오늘 잴 수 있다.

**한계 (먼저 말한다)**
시뮬 내부 A→B 는 실제 sim2real 갭의 **하한**이다. 결론은 한 방향으로만 유효하다.
여기서 무너지면 실물에서도 무너지지만, 버틴다고 실물을 보장하지 않는다.
조건 B 의 외란 크기(마찰±30%, 질량±20%, 카메라±5mm·±2°, 조명, 색±0.15)는
🟡 설계 판단이며 계측된 값이 아니다.

**되돌릴 조건**
실물 데이터 확보 후 실측 붕괴율이 이 대리 지표와 0.20 이상 어긋나면 재판정한다.

**계측기**
`sim/mujoco/domain.py`, `eval/transfer.py`, `tools/measure_transfer.py`,
`tools/check_domain.py` (커밋 `a0e4992`, `d49d018`). 게이트는 결과 확인 전 코드에
고정했다.

## D-AI-19 · 타겟 도메인을 다품종 소량생산 소형부품 취급으로 한정한다

작성자: 김준태(트랙B) · ⚠️ **AI 단독 결정 불가 — PM·HW 확인 필요**

**결정**
물리 봉투를 제품 스펙으로 명시하고 그 밖은 대상에서 뺀다.

| 항목 | 값 | 출처 |
|---|---|---|
| 대상물 크기 | 1.5 ~ 2.5cm | 그리퍼 닫힘 간격 1.7cm 실측 🟢 |
| 유효 작업면 | 15 × 35cm | reach_scan 최대 직사각형 🟢 |
| 도달 반경 | 약 0.3m | HW 실측 🟢 |
| 총질량 | 0.632kg | HW 실측 🟢 |

**제외: 물류 피킹.** 박스·봉투 크기, 팔 길이 1m+, 시간당 처리량 지표 — 셋 다
위 봉투 밖이다. 또한 전업 기업이 다수 경쟁 중인 영역이다 🔵.

**왜 다품종 소량인가**
산업용 로봇이 안 들어가는 이유는 팔 성능이 아니라 셋업 비용이다. 품목 교체가
잦을수록 "다시 가르치는 사람의 시간"이 지배적 비용이 된다. 경쟁자는 다른
로봇이 아니라 **티칭 펜던트**다.

**되돌릴 조건**
로봇팔 변경으로 그리퍼 간격 또는 도달 반경이 2배 이상 커지면 재검토.

**미검증**
지불 의사·시장 규모 (LIMITS L13), 실제 대상물 치수 (L14), 심사 기준 (L15).
발표 자료에 시장 수치를 쓰려면 조사가 먼저다. 지어내지 않는다.

## D-AI-20 · 플랫폼의 시뮬 기능을 T1/T2 로 분리한다

작성자: 김준태(트랙B) · 관련 이슈: S15P21A103-113, 65

**결정**

| | 기능 | 조건 |
|---|---|---|
| T1 | 시연 실행가능성 검사 + 재현 허용범위 표시 | **무조건 채택** |
| T2 | 시뮬 증강 학습 (등록된 5종 대상물 한정) | D-AI-18 붕괴율에 종속 |

발표 자료에서 **T2 를 확정 기능으로 표기하지 않는다.**

**왜**
T1 은 붕괴율과 무관하게 항상 동작하고, 검사기가 "재현 불가"라고 답하는 것도
정상 동작이라 실패할 수 없다. 근거 수치도 이미 있다 🟢 —
재생 성공률 ±5mm 4/4 · ±10mm 3/4 · ±15mm 1/4 · ±50mm 0/4.
T2 는 붕괴율이 0.70 을 넘으면 통째로 죽는다. 아직 안 쟀다.

**하지 않는 것**
"임의 물체를 스캔해 시뮬에 등록" 은 4주 안에 불가능하다 🟡. 제품 설명에
"임의 물체"라고 쓰지 않는다.

**되돌릴 조건**
붕괴율 ≤ 0.30 이면 T2 를 확정 기능으로 승격한다.

## D-AI-21 · UMI 포즈 취득을 ARCore 기반으로 확정 (기록)

결정 주체: 팀 기획 (김현석 전달) · 기록: 김준태(트랙B) · 관련 이슈: S15P21A103-30

**내용**
Galaxy S23 + ARCore + IMU 로 6DoF pose 를 취득한다. 이전에 검토했던 마커 기반
(ChArUco + 손가락 ArUco) 방식을 대체한다.

변환 체인: ARCore 카메라 pose × `T_cam→tcp` → t₀ 상대화 → 축 remap(Y↑→Z↑)
→ 프레임 간 델타 + 6D 회전.

**이 결정이 되살린 리스크 — 반드시 스프린트에 반영해야 한다**

1. **이미지–pose 타임스탬프 오프셋.** 마커 방식은 pose 를 이미지에서 뽑으므로
   오프셋이 구조적으로 0 이었다. ARCore 는 pose 스트림과 RGB 스트림이 별도라
   오프셋이 생긴다. 이슈 30 이 수집 전 필수 작업으로 되살아난다.
   이 프로젝트 함정 목록에 명시된 실패 양상이다 — 학습 손실은 잘 떨어지고
   실물에서만 실패해 추적이 가장 어렵다.
2. **hand-eye `T_cam→tcp`.** 오차가 궤적 전체에 **상수 편향**으로 들어간다.
   랜덤 노이즈는 학습이 평균 내 지우지만 상수 편향은 지워지지 않는다.
   실측상 ±10mm 에서 재생 성공률이 3/4 로 떨어진다 🟢.
   게이트 제안: 알려진 좌표 5점 터치, 평균 오차 ≤5mm · 최대 ≤10mm.
   손측정 근사값은 파이프라인 배선 확인용으로만 쓰고 본수집에 쓰지 않는다.
3. **SLAM 드리프트.** 세션이 길수록 누적된다. 미계측.

**계약 경계 (⚠️ 트랙 A 확인 필요)**
기획서의 액션 표현(EEF 델타 + 6D 회전 + 그리퍼, ≥10차원)과 현행 계약
(`action (6,)` 목표 관절각)은 다른 공간이다. 양립 가능하지만 경계를 문서로
못 박아야 한다 — **UMI raw = EEF pose 계열, 계약 = IK 이후 관절 공간.**
합의 없이 진행하면 양쪽이 다른 것을 만든다.

**미확인**
자유도 — 기획서는 "범용 6축", 실측 하드웨어는 SO-101 5자유도 + 그리퍼.
이슈 113 의 재현 불가 폐기율 계산이 이 값에 통째로 의존한다.
