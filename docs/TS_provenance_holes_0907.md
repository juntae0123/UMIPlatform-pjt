# TS · 5일치 "데이터 실험"이 실은 아니었다 — 어떻게 좁혔나

작성: 김준태(트랙B) · 2026-09-07 · 이슈 S15P21A103-34
확신도: 🟢 실행·로그 확인

"고쳤다"가 아니라 **어떻게 알아냈나**의 기록이다. 결론부터: 기록 체계에 구멍이
셋 있었고, 그 구멍 때문에 v2→v3→v5 를 "데이터 조건 실험"으로 잘못 부르고 있었다.

## 증상

`tools/audit_demos.py` 를 v2·v3·v5 에 각각 돌렸는데 **소수점 6자리까지 같은 수치**가
나왔다. 0.116488 / 0.000599 / n=645 / 14.6% / 0.01779 / 1.9%.

세 데이터셋이 다르면 불가능하다. 두 가능성뿐이다 — 계측기가 인자를 무시하거나,
데이터가 같거나.

## 좁히기 1 — 계측기인가 데이터인가

계측기는 데이터셋 이름을 정확히 찍었고 `sim_pick_v4`(서버에 없음)에서 "에피소드가
없다"로 정확히 실패했다. 인자는 먹고 있다. → **데이터를 의심한다.**

여기서 추론으로 답할 수 있었다: v3 의 변경은 "수집 141틱 vs 평가 165틱 갈라짐 해소"
였고 **수집 쪽은 원래 141틱**이었으므로 수집기는 안 바뀌었다. v5 는 `dwell 0.0` 이고
v2 도 `dwell 0.0` 이다. 하지만 추론으로 두면 안 된다. 해시로 대조했다.

## 좁히기 2 — 바이트 해시

에피소드 98편 전량, `state`+`action` 과 모든 `image*` 키를 따로 다이제스트했다.

```
sim_pick_v2  state+action 5dca742f59871118  image 7533ca1cbd419253
sim_pick_v3  state+action 5dca742f59871118  image 9b519e9ea47a0740
sim_pick_v5  state+action 5dca742f59871118  image 9b519e9ea47a0740
```

🟢 **v3 과 v5 는 완전히 동일하다.** v2 는 state/action 이 같고 이미지만 다르다.

즉 5일간 "데이터 조건 실험"이라 부른 것 중 **실제로 데이터를 바꾼 것은 v4(dwell)
하나뿐**이다. 나머지는 같은 데이터에 이름만 다르게 붙였고, 나는 그 이름을 근거처럼
인용했다.

## 좁히기 3 — 그럼 v3 4.3% vs v5 9.3% 는 무엇인가

같은 바이트, 같은 명목 `e30` 인데 성공률이 5%p 다르고 val_loss 도 다르다
(0.0533/0.0572/0.0694 vs 0.0531/0.0620/0.0756). 후보 둘: 학습 비결정성, 또는 코드 변경.

`EXP_LOG.jsonl` 의 `code_sha`·`config_sha`·`git_dirty` 를 대조했다.

```
2026-09-02 v2  code 83ae225c  cfg 7e5312f7  dirty=True   5.7%
2026-09-03 v3  code 5adfae82  cfg 84455d35  dirty=True   4.3%
2026-09-03 v4  code c64dc9b9  cfg 0bbb8994  dirty=True   0.0%
2026-09-07 v5  code 2931de70  cfg 3b1d6bbc  dirty=True   9.3%
```

🟢 **비결정성이 아니다** — 코드가 실제로 달랐다. 대신 더 나쁜 것이 나왔다:
**매 실행 코드와 config 가 동시에 바뀌고 트리가 전부 더러웠다.**
그래서 v3→v5 의 차이를 **어느 변경에도 귀속시킬 수 없다.** 이건 계측 실패가 아니라
프로세스 실패이고, 내 것이다.

## 좁히기 4 — 기록된 리비전이 그 코드가 아니다

v6 기록의 `git_rev` 가 `b7ffabe` 인데 **그 커밋은 잡이 시작될 때 존재하지 않았다.**
그리고 v6 의 `train_config_sha` 가 `None` 인데, 그 필드를 넣은 커밋(`66c1afd`)은
이미 서버에 있었다.

두 사실이 같은 원인을 가리킨다 — `log_run` 이 `git_rev` 와 `code_sha` 를
**로그 시점에** 계산한다. 몇 시간 도는 잡에서 그 트리는 수치를 만든 트리가 아니고,
python 이 로드한 모듈은 launch 시점의 것이다.

**틀린 코드를 가리키는 기록은 아무것도 가리키지 않는 기록보다 나쁘다.**

## 배운 것

1. **요약 통계가 같으면 원본을 해시한다.** 세 데이터셋이 같은 요약을 냈을 때
   "우연히 비슷하다"로 넘어갈 수 있었다. 6자리 일치가 아니라 3자리 일치였으면
   넘어갔을 것이다
2. **조건 비교 실행은 커밋 후에만 한다.** 더러운 트리에서 나온 수치는 비교 대상이
   아니라 참고값이다
3. **데이터셋 이름은 근거가 아니다.** `sim_pick_v5` 라는 이름이 "v5 조건"을 뜻한다고
   가정했다. 이름은 디렉터리일 뿐이고 내용은 해시가 말한다

## 추가 (같은 날) — T0 가 낸 "전면 중지"는 내 계측기 오작동이었다

`tools/probe_contract.py` 첫 실행이 `[pairing] 편차 최소 shift = -1 → 실패` 로
**전면 중지**를 냈다. 숫자를 보면 즉시 드러난다 🟢

```
shift -1   최대 편차 1.86e-09   중앙 5.82e-11   일치 20/20
shift +0   최대 편차 1.86e-09   중앙 5.82e-11   일치 20/20   ← 완전히 같다
shift +1   최대 편차 3.73e-09   중앙 3.49e-10   일치 20/20
```

동점인데 `min(shifts, key=...)` 이 목록 순서로 -1 을 골랐다. 그런데 그건 표면적
이유다. **구조적 이유는 그 편차 지표가 shift 와 무관하다는 것이다** —
`|to_action(training_target(rec_j)) − rec_j|` 는 어느 인덱스 `j` 를 썼든 그 행동의
왕복 오차이므로 페어링에 대해 아무 말도 하지 않는다.

롤아웃도 못 가른다. 세 shift 가 전부 20/20 이고 직접 재생과 일치한다 —
**절대 위치 명령의 한 틱 지연은 제어기가 흡수한다.** 이건 오늘 이미 잰 것과 같은
현상이다: 초기 관절 변위 ±0.3 rad 에서도 개루프 전문가가 87.0% 를 유지했다.

### 통과한 것은 통과했다

- `round_trip` 최대 편차 **1.86e-09** → `training_target` 과 `to_action` 이
  정확한 역이다. 표현·스케일·혼합 그리퍼 채널·클립이 전부 왕복한다 🟢
- `rollout_match` **20/20** → 정답 행동을 학습 정책의 디코드 경로로 보내도 직접
  재생과 시드별로 같은 결과다 🟢

즉 **배포 경로 디코드는 깨끗하다.** 이 부분은 유효한 계측이고, 외부 검토가
1순위로 의심했던 항목(T0)이 여기서 해소된다.

### 페어링은 코드로 해소했다

`data/collect.py` 의 루프가 4줄이다.

```python
data.ctrl[:5] = (1 - alpha) * q_start + alpha * q_target[:5]
data.ctrl[5] = gripper_cmd
rec.capture(data)      # state = qpos(스텝 전) · action = ctrl(넣은 명령)
for _ in range(sub): mujoco.mj_step(model, data)
```

`state_t` 는 `action_t` 를 적용하기 **전**의 관측이다. 계약 그대로고 인덱스 산술이
어디에도 없다 🟡 (코드 읽기이고 런타임 검증은 아니다).
sentinel action 검사는 스트림이 분리돼 off-by-one 이 실제로 가능한 **실물·UMI
경로**(S15P21A103-30)로 넘긴다.

### 오늘 이 유형의 버그가 네 번째다

1. `closing_moment` 가 연속 출력 정책에 무효 (전제 위반)
2. `probe_recovery` 의 턱접촉·밀림을 닫는 **명령이 나간 틱**에 측정 (시점 오류)
3. `probe_freeze` 의 kick 이 IK 에 막혀 무동작 (개입이 무효)
4. `probe_contract` 의 페어링 지표가 재려는 것과 무관 (지표 선택 오류)

공통점: **"무엇을 재는가"를 검증하지 않고 "얼마가 나오는가"로 갔다.**
2·4 는 특히 같다 — 잘못된 시점, 잘못된 지표. 값이 나왔다는 사실이 그 값이 그 질문에
답한다는 뜻이 아니다.
