# TS — 계측기 전제가 깨진 채로 하루를 달렸다 (2026-09-07)

작성 김준태(트랙B) · 어시스턴트 오류 기록 포함

이 문서는 "무엇을 고쳤나"가 아니라 **"어떻게 좁혔나, 그리고 왜 그 전에 헤맸나"** 다.

## 가장 비싼 것 — `closing_moment` 를 bc 에 썼다

### 무슨 일

`eval/rollout.py` 의 `closing_moment()` 은 그 에피소드 **자신의** 그리퍼 명령
최대·최소의 **중간값을 가로지르는 첫 틱**을 "닫는 순간"으로 본다.
docstring 에 전제가 적혀 있다:

> 명령은 사실상 두 수준(열기, 닫기)이라, ... 중간값을 가로지르는 시점이 닫는 순간이다.

**그 전제는 scripted 에서만 참이다.** scripted 는 −0.193 에서 −0.756 으로 계단식으로
떨어진다. bc 는 연속 회귀 출력이라 −0.20 ~ −0.50 사이를 **요동**치고, 그 요동이
중간값을 스치면 지표가 "닫았다"로 읽는다.

### 실측 🟢

seed 3000, bc, `sim_pick_v5_seed1.pt`

| | 값 |
| --- | --- |
| `close_tick` 판정 | 60 (그립 −0.4957 로 중간값 −0.478 을 스침) |
| 실제 닫힌 틱 | **102** (그립 −0.7446, 이후 유지) |
| 오차 | **42틱 = 1.4초** |

틱 66~84 에는 −0.44 → −0.25 로 **다시 열림 쪽으로 복귀**한다. 닫은 게 아니었다.

### 이 하나가 오염시킨 판단들

| 오염된 결론 | 실제 |
| --- | --- |
| "닫는 순간 거리 20.4mm — 정밀도 문제" | 닫는 순간은 xy 2.7mm 다. 정밀도는 충분했다 |
| "최근접 대비 +6.7mm 발산한다" | 발산이 아니라 지표가 다른 시점을 가리켰다 |
| "닫힌 채로 물체에 접근한다" | 접근하고 나서 닫는다. 순서는 정상이었다 |
| harness 자동 판정문 `[closing_moment] → 정밀도 문제` | bc 에 대해 **무효** |

`rollout.py` 의 게이트 판정문이 이 값으로 원인을 단정한다. **계측기가 스스로
틀린 결론을 찍고 있었다.**

### 어떻게 잡았나

**사용자가 "시뮬 영상에선 안 그랬던 것 같은데" 라고 했다.** 지표와 사람 눈이 어긋났고,
그때 지표를 의심하는 대신 계속 밀었으면 v6 를 엉뚱한 처방으로 갔을 것이다.

검증 방법: 그리퍼 명령을 **틱별로 직접 찍었다.** 요약 지표가 아니라 원계열을 봤다.

### 고칠 것

- [ ] `closing_moment` 를 연속 출력 정책에도 맞게 — 중간값 통과가 아니라
      **"닫힌 상태로 유지되기 시작한 틱"** (히스테리시스)
- [ ] 고치기 전까지 `rollout.py` 판정문에서 bc 에 대한 "정밀도 문제" 단정 제거
- [ ] 지표마다 **전제가 성립하는 정책 종류**를 docstring 에 명시

### 대응 — 도구로 막는다

| 오류 | 넣은 장치 |

| 5 | `eval/repeat.py` 조건 표류 감지 — 실행 **전에** 직전 실행과 다른 조건을 찍는다 |

3·7·8 은 도구로 못 막는다. **규칙으로 남긴다: 이름·인자·데이터 구조를 하나라도
짐작하면 명령을 주기 전에 소스에서 확인한다.** 확인 없이 준 명령은 그 자체가
미검증 코드다.

## 부수로 잡은 계측기 결함

`tracking/monitor.py` 의 `records(log: Path = EXP_LOG)` — 기본 인자가 정의 시점에
묶여 경로를 갈아끼울 수 없었다. 픽스처 테스트가 **조용히 0줄**을 반환했다.
에러가 아니라 빈 결과라서 그냥 썼으면 "기록이 없네" 하고 넘어갔다.
→ `log: Path | None = None` 로 수정, 이유를 docstring 에 남김.

## 남는 원칙

**지표와 사람의 관찰이 어긋나면 지표를 의심한다.**
그리고 요약 지표가 이상하면 **원계열을 본다.** 오늘 진짜 원인(폐루프 고정점)은
그리퍼 명령을 틱별로 찍어서야 보였다.
