# MEASURE — M1: bf16 체크포인트의 fp16 안전성 (2026-09-01)

- 작성자: 김준태 (트랙 B) · 이슈: S15P21A103-111 · S15P21A103-36
- 확신도: 🟢 실행·출력 확인
- 도구: `tools/check_vlm_fp16.py`

## 왜 쟀나

V100(sm_70)은 **bf16 연산이 없다**. 검토 중인 소형 VLM 은 전부 bf16 체크포인트라 fp16 으로
캐스팅해야 하는데, Qwen-VL 계열에서 fp16 inf/NaN·gibberish 가 보고돼 있다 🔵.
안 재고 학습을 시작하면 손실이 이상해진 뒤에야 원인을 의심하게 되고 그때는 며칠이 지나 있다.

## 조건

| 항목 | 값 |
|---|---|
| GPU | Tesla V100-PCIE-32GB (sm_70) |
| torch | 2.13.0+cu126 · `attn_implementation="sdpa"` |
| 샘플 | 20 (랜덤 224×224 uint8 이미지 + 한국어·영어 지시문 10종 순환), seed 0 |
| 비교 | 같은 입력을 fp32 / fp16 에 각각 forward → 로짓을 CPU float32 로 비교 |

## 게이트 (결과 보기 전에 코드에 고정)

```
inf/NaN 0건  AND  argmax 일치율 >= 0.99
미달이면 종료코드 1 — 그 모델은 후보에서 탈락
```

## 결과

| | **Qwen2.5-VL-3B-Instruct** | **SmolVLM2-500M-Video** | Cosmos-Reason2-2B |
|---|---|---|---|
| inf/NaN | **0** | **0** | 측정 불가 |
| 최대 절대차 | **24.558210** | **0.221292** | — |
| 평균 절대차 | 0.045467 | 0.009205 | — |
| argmax 일치율 | **0.990860** | **0.996089** | — |
| 게이트 여유 | +0.00086 | +0.00609 | — |
| **판정** | **통과** | **통과** | **접근 불가** |

Cosmos-Reason2-2B 는 **gated repo** 라 401 로 거부됐다 (`Access to model ... is restricted`).
모델 문제도 우리 코드 문제도 아니고 접근 권한 문제다. 승인 신청 후 재시도 대상.

## 읽는 법

**둘 다 통과했다. 그러나 성격이 다르다.**

- **최대 절대차가 111배 차이난다** (24.56 vs 0.22). 평균은 5배 차이인데 최대가 111배라는 것은,
  Qwen 쪽에 **일부 위치에서 크게 튀는 꼬리**가 있다는 뜻이다. 로짓 스케일에서 24 면 argmax 를
  뒤집기 충분하다.
- **게이트 여유도 7배 차이난다** (+0.00086 vs +0.00609). Qwen 은 0.99086 으로 **간신히** 넘었고,
  20샘플에서 이 정도 여유는 통계적으로 불안정하다.

## 이 측정의 한계 — 스스로 짚어둔다

**① 로짓 스케일을 기록하지 않았다.** 절대 차이만 쟀는데, 두 모델의 로짓 크기 자체가 다르면
절대차 비교가 공정하지 않다. Qwen 의 로짓이 전반적으로 크면 24 가 비율상으로는 0.22 와
비슷할 수도 있다. **상대 지표(로짓 표준편차 대비)를 추가해야 결론이 확정된다.**

**② 랜덤 노이즈 이미지가 실제보다 가혹할 수 있다.** "수치 거동만 분리한다"는 의도로 균일
노이즈를 썼는데, 자연 이미지 통계가 전혀 없어서 비전 타워 활성값이 비정상적으로 커질 수 있다.
우리 실사용 입력은 **작업대 렌더 이미지**다. 24.56 이 fp16 의 문제가 아니라 **입력 분포의 문제**일
가능성이 남아 있다.

**③ vocab 크기가 다르다.** Qwen 약 151,936 대 SmolVLM 약 49,152. 로짓 개수가 3배면 최대값이
커질 확률도 커진다. 다만 111배를 설명하기엔 부족하다.

**④ 우리가 실제로 쓰는 결정을 재지 않았다.** VLM 용도는 자유 생성이 아니라 **스킬 5개 enum 중
선택**(제약 디코딩)이다. 그러면 vocab 전체 argmax 가 아니라 **후보 토큰 사이의 순위**가
유지되는지가 실제로 중요하다. 현재 지표는 그것보다 엄격하면서 정작 그 결정을 안 재고 있다.

## 그래서 무엇이 정해졌고 무엇이 안 정해졌나

**정해진 것**: Qwen2.5-VL-3B 와 SmolVLM2-500M 은 **둘 다 V100 fp16 에서 쓸 수 있다.**
inf/NaN 이 0 이라는 것이 이 측정의 핵심 산출물이고, 이건 스케일 논쟁과 무관하게 확정이다.

**안 정해진 것**: **어느 것을 쓸지는 M1 이 정하지 못한다.** 둘 다 통과했으므로 선택 기준은
다른 데 있다 — 용도 성능(스킬 선택·grounding 정확도), Jetson 8GB 예산, 라이선스.

| 축 | Qwen2.5-VL-3B | SmolVLM2-500M |
|---|---|---|
| Jetson 예산 | Q4 약 2GB 🟡 | Q4 약 0.3GB 🟡 — 정책과 공존 여유 큼 |
| 라이선스 | **확인 필요** ⚠️ 상업 출품이라 중요하다 | **Apache-2.0** 🔵 |
| 레퍼런스 | 최다. NVIDIA 가 Orin Nano 에 직접 권장 🔵 | 적음 |
| fp16 안정성 | 통과, 여유 +0.00086 | 통과, 여유 +0.00609 |
| 용도 성능 | **미측정** | **미측정** |
