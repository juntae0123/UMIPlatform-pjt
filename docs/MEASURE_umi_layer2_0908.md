## L2-3. 변환은 사실상 무손실이다 🟢

`tools/diff_datasets.py` — 원본(시뮬 수집) vs 왕복본(UMI 경로), 19편.

```
state 왕복 최대차       1.907e-06  (계약 정규화 단위)
                        RMS 대비 0.004%  (변환본 RMS 1.602e-02 기준)
관절별 최악 비율        0.65% (wrist_roll — 분모가 작아 보조 지표)
                        나머지 0.01~0.08%

타임스탬프              완전 일치 (시뮬은 구조적으로 0)
```

**`action` 최대차는 5.725e-01 이고 이것은 정상이다.** 시뮬 수집 `action=ctrl`(낸 명령),
UMI 경로 `action=q[t+1]`(다음 관절 배치)이다. 그리퍼가 가장 크다(≈31도) — 스크립트는
계단 명령을 내고 서보가 못 따라가는데 UMI 경로는 점진적 닫힘을 라벨로 준다.
**실물에서 그리퍼가 시연보다 늦게 닫힌다는 뜻이고, 이 프로젝트는 닫는 시점이 성공을
가른다고 이미 측정했다** — 후속 계측 대상.

## L2-4. 롤아웃 0% 는 **판정이 아니다** 🟢

```
hold      0/20    0.0%
zero      0/20    0.0%
scripted 19/20   95.0%   (특권정보 — 실물 배포 불가)
bc        0/20    0.0%
게이트    ceiling 통과 · floor/chance 실패
```

**19편 / 2679샘플이다.** 시뮬·정책 대화가 98편 / 13,818샘플로 9.3% 를 얻었으므로
1/5 데이터로 0/20 은 예상 범위 안이고, n=20 에서 0/20 과 2/20 은 구분되지 않는다.
**이 실행은 정책 성능에 대해 아무것도 말하지 않는다.** 관통 검증으로서는 완주다.

실패 형태는 명확하다.

```
bc  파지점-물체 최소 수평거리 중앙 55.5mm (Q1 46.7 / Q3 63.3)
    ≤15mm 5% · >30mm 80% · 턱 접촉 5% · 닫는 순간 거리 중앙 65.5mm
scripted 실패 1건은 0.2mm
```

**접근 자체가 55mm 틀린다.** 닫는 시점 문제가 아니라 팔이 제대로 안 움직인다.

## L2-6. 데이터 속성에서 나온 실질 발견 🟢

`train_bc` 가 학습 전에 찍는 목표 분포:

```
관절별 잔차 std      0.00123  0.00269  0.00474  0.01288  0.00010  0.27666
정확히 0 인 비율        58%      11%       9%      10%      70%       0%
                     pan      lift    elbow   w_flex   w_roll   gripper
자명한 예측기(항상 0) 손실 = 0.72245  (표준화 단위)
```

**그리퍼 std 가 팔의 20~280배**고, **`shoulder_pan` 58% · `wrist_roll` 70% 가
정확히 0** 이다. `joint_delta_gripper_abs` + 타겟 표준화를 켜도 팔 목표가 스파이크라
L1·MSE 의 최적값이 0 쪽으로 끌린다.

L2-4 의 실패 형태(접근이 55mm 틀린다 = 팔이 안 움직인다)와 방향이 일치한다.
**행동 표현을 손보지 않으면 팔이 거의 안 움직이는 정책이 나온다** 🟡 — 데이터
속성과 실패 형태가 같은 방향을 가리키지만, 인과는 확정하지 않았다.

학습 손실은 0.72245 → **val 0.24909** 로 내려갔다(34%). 학습이 망가지지는 않았다.

## 계측기 정정 2건 — 내 쪽 결함이다

**1. `convert_umi` 의 `identity_mse` 안내가 단위를 틀렸다.** *"학습 손실은 이 MSE
보다 뚜렷하게 낮아야 한다"* 로 찍었는데, `train_bc` 는 `joint_delta_gripper_abs`
행동공간 + 타겟 표준화 단위로 학습하고 자체 자명한 예측기 손실(0.72245)을 이미
찍는다. **두 값은 비교 대상이 아니다.** 문구를 "데이터 속성이고 학습 손실과 직접
비교하지 마라"로 고쳤다.

**2. `diff_datasets` 의 RMS 분모가 낙관적이었다.** 왼쪽 데이터에서만 RMS 를 잡았고,
왼쪽이 시뮬 수집이면 `action=ctrl`(추종오차 포함)이라 4.6987e-02 로 크게 잡힌다.
판정 대상인 변환본은 1.602e-02 다 — **3배 차이로 비율이 3배 낙관적**이었다.
양쪽 RMS 를 다 찍고 **작은 쪽으로 나누도록** 고쳤고, 1.5배 이상 다르면 경고한다.

## 다음 계측 — 예측을 먼저 적는다

1. **98편으로 데이터량을 맞춘 뒤 시뮬 수집 원본 vs UMI 경로 A/B.**

   그리퍼 표현은 실패 원인이 아니다.
