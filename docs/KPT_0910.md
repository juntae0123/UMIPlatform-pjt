# KPT 2026-09-10 · 김준태(트랙B)

**한 줄:** 아침에 1% 던 정책이 69% 까지 갔다. 진단(L1 조건부 중앙값 붕괴)이 처방으로
확인됐다. 대신 범위 폭 63%p 와 미폐쇄 4~67/100 이 남았다.

## Keep

- **예측을 먼저 적은 것.** E1 "30~50%" → 실측 37%, v5 롤아웃 "20~30%" → 21.7%.
  맞은 것보다 **틀린 것이 기록으로 남은 게 크다** — 판정1·2 예측이 틀려서
  "이진화는 중간값 붕괴만 없앤다" 를 알게 됐다
- **계측기를 밤샘 전에 검증한 것.** `check_gripper_binary.py` 15/15 가 라벨 방향·왕복·
  표준화 예외·손실 등가를 학습 전에 확인했다. 틀렸으면 6시간이 날아갔다
- **큐 러너가 원칙을 강제한 것.** 사전등록 없으면 거부, 더러운 트리면 거부, 검증을
  전부 먼저 하고 하나라도 막히면 아무것도 시작하지 않는다
- **공짜 확인을 먼저 한 것.** oracle `never_closed=91/100` 은 이미 `result.json` 에
  있었다. 200편을 돌릴 뻔했다

## Problem

- **같은 계열 명령 결함 3회** (`PYTHONPATH`·`MUJOCO_GL` 누락). 규칙 문서를 늘리는 것으로
  두 번 실패했고, 세 번째에야 **도구에 `sys.path.insert` 를 넣어 구조로** 막았다
- **관측값을 낡은 트리 값으로 덮었다.** 앞 세션의 11/10/2 가 오늘 트리 관측값인데
  `1195c41` 트리의 14/12/2 로 "정정" 했다. `git_rev` 를 대조하지 않았다
- **`push_both.sh` 를 빠뜨렸다.** 개인 GitHub 미러가 빠지는 명령을 줬다
- **E2(계측기 수리)를 E3(진단 정교화)와 묶어 접었다.** 사용자가 뒤집었고 그게 맞았다.
  **마감 압력에서 묶으면 계측기가 먼저 잘린다**
- **사전등록에 손실을 MSE 로 적었다** (실제 `l1`). 메커니즘 서술이 평균/중앙값으로 갈린다
- **DEVLOG 를 하루 종일 안 쓰고 지적받았다.** ⚠️ `KPT_0907` 의 Problem 에 **같은 항목이
  이미 있다.** 규칙만 적어두면 반복된다는 증거다

## Try

1. **도구는 호출자 환경에 의존하지 않게 만든다.** 명령에 변수를 덧붙이는 규칙은 3번 실패했다.
   새 `tools/*.py` 는 `sys.path.insert` 를 넣고, 필요한 env 는 스크립트가 스스로 export 한다
2. **EXP_LOG 수치를 인용할 때 `git_rev` 를 현재 HEAD 와 대조한다.** 대조 안 한 값은
   fixture·비교 기준으로 쓰지 않는다. 트리가 다르면 옮기지 말고 다시 잰다
3. **"계측기 수리"와 "진단 정교화"를 분리해서 판단한다.** 묶으면 계측기가 먼저 잘린다
4. **다음 계측 순서: oracle-best-tick → 손실 항 분리 → 그리퍼 확률 덤프.**
   순서 근거는 `HANDOVER_0911_gripper.md` §2
5. **분산을 n 으로 풀려 하지 않는다.** dagger 폭 63%p 는 정밀도가 아니라 학습 불안정이다.
   5회 확장 대신 seed0 이 무너진 지점을 계측한다
6. **DEVLOG 상태 보드를 매 턴 갱신한다.** 0907 에 같은 Problem 이 있었으므로 이번엔
   규칙을 파일 첫머리에 박았다 — "여기 없으면 안 한 것이다"
