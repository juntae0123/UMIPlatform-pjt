## M1. 관절 범위 — MJCF vs configs 대조 🟢

`verify_against_config()` 결과 **불일치 0건**. `configs/so101.yaml`의 6축 range_rad가
컴파일된 모델의 `jnt_range`와 1e-9 이내로 일치한다.

```
shoulder_pan  [-1.9198621771937616,  1.9198621771937634]
shoulder_lift [-1.7453292519943224,  1.7453292519943366]
elbow_flex    [-1.69,                1.69              ]
wrist_flex    [-1.6580628494556928,  1.6580627293335335]
wrist_roll    [-2.7438472969992493,  2.841206309382605 ]
gripper       [-0.17453297762778586, 1.7453291995659765]
```

**주의:** actuator `ctrlrange`는 5자리로 반올림돼 있어 joint range와 최대 ~3e-6 rad 차이가 난다.
`wrist_roll`의 ctrlrange 하한 `-2.74385`는 joint 하한 `-2.7438472...`보다 미세하게 **바깥쪽**이다.
정본은 joint range로 고정했다.

## M2. 공식 MJCF에 카메라가 0개 🟢

`grep '<camera'` 결과 0건. 데이터 규격은 `image (3,224,224) × 2대`인데
공식 배포본에는 카메라가 하나도 없다. 전부 우리가 추가해야 한다.

## M3. MJCF include로는 손목 카메라를 붙일 수 없다 🟢

`include`된 파일 안의 body(`gripper`)를 다시 열 수 없다. 씬 XML에 손목 카메라를
선언할 방법이 없다. 두 가지 선택지뿐이었다:

1. 공식 MJCF를 직접 수정 → **프로젝트 규칙 위반** (공식 파일은 include만, 수정 금지)
2. 로드 시점에 `mujoco.MjSpec`으로 주입 → **채택**

`build_scene.py`가 `configs/so101.yaml`을 읽어 두 카메라를 모두 주입한다.
카메라 값이 XML과 config 두 곳에 갈라지지 않게 씬 XML에는 카메라를 하나도 두지 않았다.

> 작업 중 실제로 이 함정을 밟았다. 처음엔 `cam_front`만 XML에 두고 config에도 적었는데,
> config를 고쳐도 렌더 결과가 안 바뀌었다. XML 값이 이기고 있었기 때문이다.

## M4. 휴식자세(qpos=0) 기하 실측 🟢

new_calib 기준 qpos=0은 팔이 **앞으로 뻗은** 자세다. 접힌 자세가 아니다.

| 항목 | 값 (m) |
|---|---|
| TCP (`gripperframe` site) | (0.3914, -0.0000, 0.2265) |
| gripper body 원점 | (0.2932, -0.0002, 0.2344) |
| 로봇 geom x 범위 | [-0.0286, 0.3413] |
| 로봇 geom z 범위 | [0.0167, 0.2531] |

gripper body 로컬축: `local -z` = 손가락 방향, `local +x` = 월드 위쪽, TCP = local (-0.0079, 0, -0.0981).

## M5. 손목 카메라는 그리퍼 메시 안에 들어간다 🟢

첫 배치 local (0.045, 0, 0.03)은 gripper 메시 hull(중심 local (-0.0098, 0, -0.0282), rbound 0.0843)
**안쪽**이었다. 거리 0.0799 < 0.0843. 렌더 결과가 노란 메시로 꽉 찼다.

local (0.06, -0.07, 0.02)로 옮기니 거리 0.110 > 0.0843, 턱과 물체가 보인다.

⚠️ 이 값은 **시뮬 전용 잠정값**이다. 실물 카메라 마운트 형상이 확정되면 재계측해야 한다.

## M6. 파지직전 자세 도달 가능성 🟢

물체 (0.22, 0, 0.0099) 위 6cm 지점 (0.22, 0, 0.0799)에 대해 DLS IK:

| 항목 | 값 |
|---|---|
| 최종 위치 오차 | **0.75 mm** |
| 관절 한계 내 | **True** (전 축이 한계에서 떨어져 있음) |
| 반복 | ≤300, damping 1e-2 |

qpos (rad): `[-0.0001, -0.8830, 0.8901, 0.9468, 0.0008, -0.0000]`
정규화 후: `[-0.0001, -0.5059, 0.5267, 0.5710, -0.0171, -0.8182]`

이 IK 루틴이 "사람 궤적을 로봇이 재현 가능한가" 검사 도구의 씨앗이다.

## M7. 정규화 규칙 검증 🟢

`gripper` qpos = 0 rad → 정규화 **-0.818**. 닫힘(-0.1745 rad)이 -1.0에 대응하므로 일관적이다.
6축 전부 동일 규칙(`x_norm = 2(x-lo)/(hi-lo) - 1`)을 쓴다. 그리퍼 특별 취급 없음.

## 산출물 재현

렌더 이미지는 **저장소에 커밋하지 않는다**(`AI/.gitignore`의 `out/`). 아래 명령으로 재생성한다.

```bash
pip install -r AI/requirements-sim.txt
MUJOCO_GL=egl PYTHONPATH=AI/scripts python AI/scripts/render_check.py --out AI/out
```

생성 파일 (224x224, 카메라 2대 x 자세 2종):

| 파일 | 내용 |
|---|---|
| `AI/out/rest_cam_front.png` | 휴식자세, 고정 3인칭 |
| `AI/out/rest_cam_wrist.png` | 휴식자세, 손목 |
| `AI/out/pregrasp_cam_front.png` | 파지직전, 고정 3인칭 |
| `AI/out/pregrasp_cam_wrist.png` | 파지직전, 손목 |

같은 명령이 M1(관절범위 대조)과 M6(IK 도달성)도 함께 출력한다. 위 수치와 다르면
`configs/so101.yaml`이나 공식 MJCF가 바뀐 것이다.
