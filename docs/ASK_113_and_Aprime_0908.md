## 0. 당신에게 부탁하는 것과, 반드시 지켜야 할 규칙

두 개의 독립된 과제가 있다. **§3(과제 113)** 과 **§4(과제 A′)**. 둘은 서로 의존하지 않는다.
각각에 대해 §3.7 / §4.6 의 질문에 답해 달라.

### 이 프로젝트가 비싸게 배운 규칙 — 답변도 여기에 맞춰 달라

1. **평가 지표는 롤아웃 성공률이다. validation loss 가 아니다.**
   실증 🟢 2026-09-01: val_loss 를 0.00547 → 0.00517 로 낮췄는데 롤아웃은 0% 그대로였다.
   독립 학습 2회 재현. val loss 는 "학습이 망가지지 않았나" 확인용으로만 쓴다.
   **loss 를 근거로 한 제안은 채택하지 않는다.**

2. **신뢰구간이 겹치면 구분된 것이 아니다.**
   n=20, p≈0.8 이면 95% CI 반폭이 ±18%p 다. "95%" 는 실제로 "77~99%" 로 읽어야 한다.
   Wilson CI 로 판정하고, 겹치면 "차이 없음"이 아니라 **"구분 불가"** 라고 쓴다.

3. **게이트를 옮기지 말고 n 을 올려라.**
   결과를 보고 기준을 바꾸는 것은 사후 합리화다. n 증가는 정밀도 개선이다. 다른 문제다.

4. **게이트는 결과를 보기 전에 코드에 박는다.** 사전등록. 분기 규칙까지 미리 쓴다.

5. **기전 주장은 계측되기 전까지 🟡 다.**
   확신도 표기: 🟢 실행·로그 확인(계측기 이름 병기) / 🔵 문서·공개자료 / 🟡 설계 판단만.
   어제 하루에만 내가 기전 설명을 6번 철회했다. 측정값은 0번 철회했다.
   **차이는 "무엇을 쟀나"와 "왜 그런가"를 섞었다는 것이다.** 당신도 섞지 말아 달라.

6. **대책보다 계측기를 먼저 제안하라.** "이렇게 고치면 된다"보다
   "이게 틀렸다면 무엇이 어떻게 보이는가"를 재는 방법이 먼저다.

7. **계측기를 쓰기 전에 계측기를 검증한다.** 고장난 계측기는 스스로 알리지 않는다.
   어제 내 계측기 버그 7건이 전부 "그럴듯한 숫자"를 냈다. 그중 3건은 결론까지 냈다가 철회했다.

8. 같은 데이터·설정으로도 **학습 실행 간 성공률이 25%p 갈린다** 🟢.
   단일 학습의 단일 롤아웃으로 체크포인트를 비교하지 마라. 학습 3회 + 평균·범위가 기본이다.
   그리고 **3 vs 3 순열검정의 최소 단측 p 는 1/C(6,3) = 0.05** 다 —
   3시드로는 구조적으로 조건 순위를 매길 수 없다.

9. 모든 수치에 **측정 조건 병기.** 조건 없는 절대값 인용 금지.

### 1.4 데이터 계약 (`AI/contract/episode.py` 가 정본, `CONTRACT_VERSION = "0.2.0-provisional"`)

```
관측  image  (3,224,224) uint8 CHW × 카메라 2대
      state  (6,) float32   관절 6개, [-1,1] 정규화
      state_timestamp  (T,) float64 초
행동  action (6,) float32   목표 관절각 5개 + 그리퍼, [-1,1]
      action_timestamp (T,) float64 초
주기  30Hz · RANGE_TOLERANCE 1e-4
```

**action 은 절대 관절각(명령), state 는 측정값이다.** 그래서 `action − state` 는
"움직임"이 아니라 **추종 오차**다. 이 구분을 어제 내가 한 번 틀렸다.

⚠️ 이 규격이 바뀌면 수집한 데이터가 전부 무효다. 변경은 양 트랙 합의 + 결정기록이 필요하다.

### 1.5 IK API (`sim/mujoco/kinematics.py`) — 두 과제 모두 이걸 쓴다

```python
def solve_pose_ik(model, target_xyz, offset_local, desired_axis, q_init=None,
                  wrist_roll=None, max_iters=500, damping=5e-3, axis_weight=0.15,
                  pos_tol=1e-3, axis_tol_deg=1.0) -> IKResult

@dataclass(frozen=True)
class IKResult:
    qpos: np.ndarray
    pos_error_m: float
    axis_error_deg: float
    within_limits: bool
    POS_TOL_M   = 5e-3      # 예산
    AXIS_TOL_DEG = 5.0      # 예산
    @property
    def ok(self):
        return (pos_error_m < POS_TOL_M and axis_error_deg < AXIS_TOL_DEG
                and within_limits)
```

감쇠 최소자승이 `[e_pos ; axis_weight · e_axis]` 를 줄인다. `axis_weight = 0.15` 가 기본값.

**자유도 배분 실측 🟢** (`umi_roll_study.py`, 무작위 40자세 × 15각도):

```
wrist_roll 만 흔들 때   파지점 이동 0.0000mm   접근축 변화 0.000도   턱축 변화 88.57도
wrist_flex 만 흔들 때   파지점 이동 282.06mm   접근축 변화 176.43도
```

→ `wrist_roll` 은 위치·접근축과 **결합이 정확히 0** 이다
(`pinch_offset_local` 이 roll 축 위에 있어서). 실제 계는 **4관절 / 5구속(과결정)** 이고,
roll 은 완전 독립이라 항상 맞출 수 있다.
⚠️ 이 분해는 파지점이 roll 축 위에 있다는 데 의존한다. **로봇팔 변형 시 무효.**

### 2.7 얼어붙음(freeze) 계측 🟢 (`probe_freeze`, n=100)

## 3. 과제 1 — UMI 실행가능성 검사기 (이슈 S15P21A103-113)

### 3.1 무엇을 답해야 하나 — 미들웨어 담당자가 막혀 있다

MW 담당자가 실제 UMI 그리퍼로 시연을 찍어서 보내왔고, 세 가지를 물었다:

- **(a) 이 시연의 몇 %가 로봇으로 실행 가능한가?**
- **(b) 안 되는 프레임은 왜 안 되는가?**
- **(c) 어느 관절이 걸리는가?**

이 답이 없으면 본수집 프로토콜을 못 정한다. **수집 착수 전에 실행가능성 검사 도구가 있어야 한다** —
사람 손 궤적을 로봇이 재현하지 못할 수 있고, 못 하는 걸 나중에 알면 데이터 전체가 버려진다.

### 3.2 이미 만들어져 있는 것 — 다시 만들지 마라

브랜치 `feature/ai/S15P21A103-127-umi-passthrough` 에 UMI raw → 계약 변환기가 있다.

```
AI/umi/raw.py       RawEpisode 스키마 + validate_raw / require_convertible / read_raw / write_raw
AI/umi/ik.py        쿼터니언↔행렬, approach_axis_from_quat, jaw_axis_from_quat,
                    roll_residual_deg, IKSolution, IKSolver(Protocol), ResidualSummary
AI/umi/convert.py   convert(), ConversionPolicy, ConversionReport, 정규화·gap 역곡선
AI/tools/           convert_umi · check_umi_convert · make_umi_synth · umi_mujoco
                    umi_reach_study · umi_roll_study · umi_diagnose_ik
```

핵심 자료구조:

```python
@dataclass
class RawEpisode:
    meta: RawMeta            # recording_id, skill_id, source, frame, n_steps,
                             # pose_rate_hz, cameras, calibration_id, device, ...
    eef_pos: np.ndarray            # (T,3) float64, metres, meta.frame 기준
    eef_quat: np.ndarray           # (T,4) float64, **wxyz**, 단위 사원수
    gripper_gap_m: np.ndarray      # (T,) 손가락 간격 [m]
    pose_timestamp: np.ndarray     # (T,) float64 초
    images: dict[str, np.ndarray]  # cam -> (Ti,H,W,3) uint8
    image_timestamp: dict[str, np.ndarray]

@dataclass(frozen=True)
class IKSolution:
    q_rad, pos_error_m, axis_error_deg, roll_residual_deg, within_limits, converged
    @property
    def ok(self) -> bool

@dataclass
class ConversionReport:
    recording_id, n_steps_in, n_steps_out
    rejects: dict[str, int]
    kept_span: tuple[int, int]
    residual: ResidualSummary
    image_sync_offset_ms, identity_residual
    def acceptance_rate(self) -> float
```

거부 사유는 이미 4종으로 분류된다:

```
ik_not_converged · ik_joint_limit · ik_pos_error_over_budget · gripper_gap_outside_curve
```

**즉 (a)와 (b)의 계측기는 이미 있다.** (c)"어느 관절"만 없다 —

## 4. 과제 2 — 잔차 주입 실험 (A′)

### 4.1 풀려는 문제

**BC 롤아웃이 0% 인데 val loss 는 낮다.** (98편 13,818샘플, val 0.00517, 롤아웃 0/20)

배제된 원인:

| 후보 | 상태 | 근거 |
|---|---|---|
| 계약·스케일·배포 경로 | **배제** 🟢 | T0: round_trip 1.86e-09, rollout_match 20/20 (§2.5) |
| 시연 데이터가 원래 실패 | **배제** 🟢 | 98/98 편 들어올리기 성공 (§2.4) |
| 데이터셋이 실제로 달랐음 | **배제** 🟢 | 바이트 해시 동일 (§2.2) |
| 스레드 수 / 비결정성 | **배제** 🟢 | threads 1 == 8 비트 동일 (§2.6) |
| 얼어붙어서 못 함 | **거의 배제** 🟢 | freeze 11%, 진짜 파지 후는 4%. 기여 천장 약 6%p (§2.7) |
| 이미지 증강 부족 | **기각** 🟢 | v6 증강 5.7%, v5 와 CI 겹침 (§2.2) |
| **누적 오차 / covariate shift** | **미검증** ← 이번 대상 |

즉 남은 유력 후보가 **"작은 예측 오차가 롤아웃 동안 누적되어 시연 분포 밖으로 나간다"** 다.
이건 모방학습의 교과서적 실패 양상이고, 사실이면 대책은 DAgger / action chunking 이다.
**둘 다 며칠짜리다. 그래서 착수 전에 이 가설이 맞는지 반나절로 재고 싶다.**

### 4.2 설계 — 무엇을 하려는가

교사강요 상태에서 BC 가 내는 **실제 크기의 잔차**를, 기록된 action 재생에 주입해서
궤적이 그 크기의 오차로 무너지는지 본다.

```
기준선:  물체를 notes.object_init_xy 에 고정 + 기록된 action 재생  →  98/98 성공 🟢
A′   :  같은 재생에 잔차 r_t 를 더한다  →  성공률이 어떻게 떨어지나
```

잔차 크기의 출처: `eval/trace_execution.py` 의 **section B** 가 이미 잰다.
기록된 모든 관측에서 네트워크에 물어보고 관절별 평균 절대오차를 낸다:

```python
err   += |pred - ep.action[t]|          # 관절별 예측 오차
delta += |ep.action[t] - ep.state[t]|   # 관절별 추종 오차 (규모 기준)
ratio  = err.sum() / delta.sum()        # 게이트 B_RATIO_MAX
```

주입은 **T0 로 검증된 배포 경로**(`training_target` → 스케일 → `to_action`)를 그대로 통과시킨다.
새 경로를 만들면 T0 가 무효가 된다.

잔차 모형 세 가지 (여기가 핵심):

- **(a) i.i.d. 가우시안** — 관절별 σ 를 section B 의 err 에 맞춤
- **(b) 위상 조건부** — APPROACH / DESCEND / CLOSE / LIFT 단계별 σ
- **(c) 블록 부트스트랩** — 실제 BC 잔차 시퀀스를 블록 단위로 재표집.
  **시간 상관을 보존한다.**

(c)가 중요한 이유: **i.i.d. 노이즈는 평균으로 지워지지만 상관된 편향은 궤적 전체를 민다.**
같은 크기라도 결과가 다를 것이라고 본다 🟡. 실측된 유사 사례가 있다 —
hand-eye 상수 편향은 ±10mm 에서 재생 성공률을 3/4 로 떨어뜨린다(§2.1).

배율 스윕: **0 · 0.25× · 0.5× · 1× · 2×** (1× = section B 실측 크기), 각 n=100, 시드 고정.

### 4.3 사전등록할 판정 규칙 (초안 — 당신의 검토 대상)

```
1× 블록부트스트랩에서 성공률이 50% 미만으로 떨어지면
    → "BC 크기의 상관 잔차만으로 궤적이 무너진다"가 성립
    → 누적 오차가 충분한 설명. DAgger / 청킹 착수 정당화

1× 에서 성공률이 90% 이상 유지되면
    → 누적 오차는 충분한 설명이 아니다
    → 표현(관측 인코딩) 또는 타이밍 쪽으로 수사 방향 전환

그 사이(50~90%) → 판정 보류. n 을 올리고 배율 해상도를 높인다
```

### 4.4 비대칭 판독 규칙 — 이걸 꼭 지키고 싶다

**무너지면 강한 증거다. 안 무너져도 covariate shift 를 배제하지 못한다.**

이유: section B 의 잔차는 **교사강요(on-distribution) 상태**에서 잰 것이다.
롤아웃에서 궤적이 분포 밖으로 나가면 그때의 오차는 이보다 크다.
즉 **1× 는 진짜 롤아웃 오차의 하한**이다. 하한으로 무너지면 확실하고,
하한을 버틴다고 상한을 버틴다는 뜻은 아니다.

이 비대칭을 결론 문장에 명시적으로 쓸 것이다.

### 4.5 알고 있는 함정

- 물체를 고정하면 재생이 100% 다. 즉 **기준선에 헤드룸이 0** 이라 하락만 관측된다. 의도한 것이다.
- 잔차를 어느 공간에 주입하나 — 정규화 [-1,1] 공간인가, rad 공간인가.
  관절 범위가 서로 달라서 결과가 달라진다.
- 그리퍼(인덱스 5)에 잔차를 주입하면 파지 자체가 깨져서 다른 실패 모드가 섞인다.
  팔 5관절만 주입할지, 전부 할지.
- `action` 은 절대 관절각이다. **절대 표현은 정밀도를 숨긴다** — 손실 대부분이
  "팔이 지금 어디 있나"로 채워지고 실제 움직임을 만드는 잔차 `action − state` 는 틀린 채 남는다.
  이 실험이 재는 것은 후자 쪽 민감도다.

### 4.6 당신에게 묻는 것 (과제 A′)

**Q7. 이 실험이 실제로 covariate shift 를 재는가?**
