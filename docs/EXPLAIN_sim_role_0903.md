# 시뮬레이션이 UMI 모방학습에서 하는 일 — 발표자용 설명

작성: 김준태(AI 트랙B) · 2026-09-03 · 근거 D-AI-18, D-AI-29

## 오해를 먼저 정리한다

> ❌ "시뮬레이션으로 UMI 학습을 한다"

아니다. **정책의 가중치는 사람 시연에서 온다.** 시뮬은 학습 데이터를 대신하지 않는다.

> ✅ "UMI 시연이 학습 데이터다. 시뮬은 그 학습을 **세 지점에서 따로** 돕는다"

## 한 장 그림

```
                     ┌──────────────── 시뮬레이션 ────────────────┐
                     │                                            │
   사람 시연         │  ① 실행가능성 검사        ② 평가 하니스     │
   (Galaxy S23)      │     쓸 수 있는 시연만        실물 없이 채점  │
        │            │            ↓                      ↑        │
        ▼            │            │                      │        │
   ┌─────────┐       │            │                      │        │
   │ 시연 데이터 │─────┼────────────┴──▶ 학습 ──▶ 정책 ────┘        │
   └─────────┘       │                   ▲                        │
   ★ 여기가 학습 데이터 │                   │                        │
                     │            ③ 사전학습 (판정 대기)            │
                     │               가중치 출발점만 채움           │
                     └────────────────────────────────────────────┘
```

**★ 표시가 학습 데이터다. 시뮬은 그 자리에 없다.**

## 세 가지 역할 — 성격이 완전히 다르다

| | 하는 일 | 학습과의 관계 | 상태 |
|---|---|---|---|
| **① 실행가능성 검사** | 사람 손 궤적을 로봇이 재현할 수 있는지 시뮬에서 미리 돌려본다. 못 하는 시연은 걸러낸다 | **학습 전.** 데이터 품질 | 채택 (D-AI-18 S1) |
| **② 평가 하니스** | 학습된 정책을 실물 없이 수백 번 돌려 성공률을 낸다 | **학습 후.** 채점 | 채택 (D-AI-18 S2) |
| **③ 사전학습** | 시뮬로 먼저 학습해 가중치를 채운 뒤, 그 위에 사람 시연으로 파인튜닝 | **학습 중.** 이게 유일한 "보조학습" | **판정 대기** (D-AI-18 S3) |

①②는 붕괴율·성능과 무관하게 **항상 동작한다.** 실패할 수 없는 종류다 —
검사기가 "재현 불가"라고 답하는 것도 정상 동작이다.
③만 "도움이 되는가"를 측정해야 한다.

## ③을 한 줄로

**시뮬은 "팔을 어떻게 움직이는가"를 가르치고, UMI 시연은 "이 작업을 어떻게 하는가"를 가르친다.**

로봇 팔이 관절을 움직이면 카메라 화면이 어떻게 바뀌는지, 물체에 가까워지려면 어느 관절을
얼마나 돌려야 하는지 — 이건 작업과 무관한 기초다. 시뮬에서 사람 손이 전혀 안 들어가고
무한히 만들 수 있다. 그 기초가 채워진 상태에서 사람 시연을 주면, 시연은 작업만 가르치면 된다.

## 왜 이게 제품 가치인가

우리 타겟은 **다품종 소량생산**이다. 제품이 자주 바뀌고, 바뀔 때마다 시연을 다시 해야 하고,
**그때 시연을 100편씩 할 수 없다.** 그래서 ③의 목표는 성능이 아니라 **시연 수 절감**이다.

| 우리가 재는 것 | 안 재는 것 |
|---|---|
| 롤아웃 **성공률** | ~~학습 시간~~ — GPU 시간은 우리 비용이고 고객 가치가 아니다 |
| 게이트 도달에 필요한 **실시연 수** | ~~시뮬 성공률 자체~~ — 실물 갭의 하한일 뿐이다 |

## ③의 게이트 — 결과 보기 전에 박았다 (D-AI-29)

| | 기준 |
|---|---|
| G1 | 같은 시연 수에서 성공률 **+20%p 이상** |
| G2 | 같은 성공률에 필요한 실시연 수 **40% 이상 감소** |

둘 중 하나를 넘으면 **"실물에서 시도해볼 자격을 얻었다"**고 기록한다.
**"검증 완료"가 아니다** — 시뮬 결과는 실제 sim2real 갭의 하한이고, 실물 성능은
실물 롤아웃 n=100 이 판정한다. 넘지 못하면 **③은 기각하고 자원을 UMI 실데이터로
돌린다.** 그것도 결과다.

두 조건이 더 붙는다 (2026-09-03 신현우 지적 수용, D-AI-29 개정 1차):

- **평가 조건을 사전학습에서 뺀다.** 사전학습이 평가에 쓰는 물체 위치·자세를 덮으면
  ③의 기여가 부풀어 오른다. 안 본 위치(보간)와 학습 범위 밖(외삽)을 따로 보고한다
- **대조군은 "같은 모델 · 같은 실데이터 · 시뮬만 뺀 것"이다.** scratch 와 비교하면
  모델 자체의 사전학습 효과가 시뮬 공으로 잡힌다

## 발표에서 말하면 안 되는 것

- "시뮬로 학습해서 실물에서 동작한다" — 미검증. 실물 롤아웃 0회다
- "시뮬 성공률 84%" — 그건 `scripted` 이고 물체 위치를 특권 정보로 읽는다. 실물 배포 불가
- ③을 확정 기능으로 표기 — 판정 전이다 (D-AI-20 에서 이미 금지)

## 발표에서 말할 수 있는 것

- ①②는 확정. 시뮬은 이미 데이터 품질과 평가에 쓰이고 있다
- ③은 게이트를 숫자로 박아두고 측정 대기 중. **기준을 결과 전에 정했다는 것 자체가 방법론이다**
- 현재 시뮬 정책 성공률 9.3% (n=300, 학습 3회 × 평가 3회 합산), 배포 게이트 20%
