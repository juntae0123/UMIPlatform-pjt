
⚠️ **실행 환경이 프로젝트 표준이 아니다.** 데스크톱 Cowork VM 의 Python 3.10.12 에

## 무엇을 재는 계측인가 — 그리고 무엇을 재는 게 아닌가

유효한 관절 배치에서 FK 로 EEF pose 를 만들고 IK 로 되돌린다.
그 pose 는 **5자유도 다양체 위에 정확히 놓여 있어 도달 가능성이 구조적으로 보장된다.**

- 재는 것: 좌표계·오프셋·부호 규약이 맞는가, 솔버가 어디까지 내려가는가
- **재지 않는 것: 사람 UMI 궤적의 실행 가능성.** 이 수치를 UMI 성능으로 인용하지 않는다.
  실제 사람 손 pose 는 이 다양체 밖에 있고, 그 수용률은 S15P21A103-113 소관이다

## M1. 솔버 정지 허용오차가 왕복 오차의 천장이었다 🟢

`solve_pose_ik` 기본값으로 먼저 쟀고, 분포가 1.0mm 에 몰려 있었다.

| 조건 | 위치 중앙 | p95 | 최대 | 접근축 중앙 | 미수렴 |
|---|---|---|---|---|---|
| `pos_tol=1e-3` (sim 기본값) | 0.830mm | 0.983 | 0.9989 | 0.309도 | 0/450 |
| `pos_tol=1e-5, axis_tol=0.05도` | **0.0088mm** | 0.0099 | 0.0100 | **0.0035도** | 0/450 |

**해석:** 0.830mm 는 기하가 아니라 조기종료 기준이다. 최대값이 0.9989 로 천장에
붙어 있고 미수렴이 0 이라 반복 여유가 남아 있었다. 1mm 는 변환 예산 5mm 의 20%
이고, 재생 허용오차 ±10mm 의 10% 다 — 아무것도 안 하고 쓰는 값이었다.

조인 뒤에도 값은 여전히 새 허용오차(0.010mm)에 붙어 있다. 더 내릴 수 있지만
0.0088mm 는 예산의 0.18% 라 내릴 이유가 없다.

**`solve_pose_ik` 의 기본값은 바꾸지 않았다.** 그 함수는 시뮬·정책 대화 소유이고
스크립트 수집이 그 기본값으로 검증돼 있다. `tools/umi_mujoco.py` 의 `MujocoIK` 가
인자로 덮고, 그 값을 실행 조건으로 기록한다.

## M2. 계측기가 거짓말했다 — roll 잔차의 180도 대칭 🟢

평행 그리퍼의 턱 축은 **방향이 없다.** 접근축 둘레로 180도 돌리면 두 턱이 자리를
바꿀 뿐 같은 파지다. `roll_residual_deg` 가 `[0,180]` 으로 재고 있어서 멀쩡한
파지를 큰 오차로 보고했다.

| | 접기 전 | 접기 후 `[0,90]` |
|---|---|---|
| roll 잔차 중앙 | 46.78도 | 46.98도 |
| roll 잔차 p95 | 106.59도 | **82.05도** |

중앙값은 거의 안 변했다(46.8 < 90). p95 는 106.6 → 82.0. 접기가 분포를 단순히
`180-x` 로 뒤집는 게 아니라서 사전 추정(73도)은 틀렸다.

## M3. 왕복은 pose 를 복원하지만 관절 배치를 복원하지 않는다 🟢

```
관절각 복원 최대오차 (팔 5축)  2.204 rad = 126.3도
```

위치 오차가 0.0088mm 인데 관절각이 126도 다르다. IK 가 **다른 해 분기**로 수렴한
것이다. 위치 3 + 접근축 2 = 5 구속에 자유관절 5개면 해가 이산집합이고, 같은 파지점·
같은 손가락 방향을 다른 팔 자세로 만들 수 있다.

**따라서 왕복 오차를 "IK 가 시연자의 팔 자세를 복원한다"는 근거로 쓸 수 없다.**

## M4. roll 잔차 47도는 5자유도 한계가 아니다 — **원인은 야코비안의 널 방향이었다** 🟢

> **정정 2026-09-07:** 이 절의 최초 결론("분기 선택 실패")도 틀렸다. M5 가 원인을
> 확정했고 M6 이 해소했다. 아래는 관측 사실만 남긴다.

이번 입력의 6자유도 pose 는 **유효한 관절 배치에서 나왔으므로 전부 달성 가능**했다.
그런데도 roll 잔차 중앙값이 47도다. `wrist_roll` 을 풀이에 열어둔 결과 솔버가
아무 분기로나 수렴했고, 되돌릴 수 있었던 정보를 버렸다.

실물 UMI 는 다르다 — 사람 손 pose 는 다양체 밖이라 roll 이 원리적으로 안 맞는다.
하지만 **이 계측에서의 47도는 원리가 아니라 분기 선택 실패다.**

중요도: 2cm 정육면체는 대칭이라 roll 이 무관하다. 타겟 도메인은
**다품종 소량생산 소형부품**이고 비대칭 부품은 턱이 특정 방향으로 물어야 한다.
`solve_pose_ik` docstring 이 "wrist_roll 은 턱이 열리는 방향을 고르는 유일한
수단이다"라고 명시한다.

## M5. 자유도 배분이 알려진 것과 다르다 — 직접 쟀다 🟢

`wrist_roll` 하나만 흔들고 나머지를 고정했다. 무작위 40자세 x 15각도.

| 흔든 관절 | 파지점 이동 최대 | 접근축 변화 최대 | 턱축 변화 최대 |
|---|---|---|---|
| `wrist_roll` | **0.0000 mm** | **0.000 도** | 88.57 도 |
| `wrist_flex` | 282.06 mm | 176.43 도 | 89.60 도 |
| `elbow_flex` | 551.93 mm | 179.83 도 | 89.83 도 |

`wrist_roll` 은 파지점과 접근축에 **영향이 정확히 0** 이고 턱 방향만 바꾼다.
`grasp.pinch_offset_local = [0, 0, -0.08]` 이 roll 축(그리퍼 로컬 z) 위에 정확히
놓여 있고 접근축이 그 축이기 때문이다.

**따라서 실제 자유도 배분은 이렇다.**

```
pan · lift · elbow_flex · wrist_flex (4개)  →  위치 3 + 접근축 2 = 5구속  (과결정)
wrist_roll (1개)                            →  roll 전담, 완전 독립 제어
```

두 가지가 따라온다.

1. **roll 은 버릴 필요가 없다.** 공짜로 맞출 수 있다
2. **`wrist_roll` 을 풀이의 자유변수에 넣으면 해롭다.** 야코비안에 영향 0 인 열이
   생기고 감쇠 최소자승이 그 널 방향으로 표류한다. **M4 의 47도가 그것이다**

⚠️ 이 분해는 파지점이 roll 축 위에 있다는 데 전적으로 의존한다. **로봇팔 변형
   예정**이므로 그리퍼 형상이 바뀌면 무너진다. 재측정 대상이다.

⚠️ `sim/mujoco/kinematics.py` docstring 은 "위치 3 + 접근방향 2 = 5로 정확히
   결정된다 / 접근축 둘레 회전은 wrist_roll 명령 그대로일 뿐, 나머지 다섯과
   **독립적으로 고를 수 없다**"고 쓰고 있다. 뒷부분이 실측과 다르다.
   그 파일은 시뮬·정책 대화 소유이므로 고치지 않고 "변경 예고"로 전달했다.

## M6. 1회 보정으로 roll 을 정확히 맞춘다 🟢

roll 이 `wrist_roll` 에 선형이고 결합이 0 이므로 탐색도 반복도 필요 없다.
자유 풀이 후 부호 있는 roll 오차를 재서 `wrist_roll` 에 한 번 더하면 끝난다.

부호는 **재서 정했다.** 유도하지 않았다 — `wrist_roll` 은 로컬 +z 둘레로 돌고
접근축은 로컬 -z 라서 어딘가에서 뒤집히고, 어느 쪽인지는 MJCF 축 규약에 달렸다.

| 부호 | roll 잔차 중앙 | p95 | 위치 중앙 |
|---|---|---|---|
| `+1` | 56.0068도 | 88.0767 | 0.0084mm |
| **`-1`** | **0.0000도** | **0.0000** | 0.0084mm |

세 전략 대조 (n=100, 목표 pose 를 접근축 둘레로 δ 만큼 돌려 roll 을 달성 불가로 밀었다):

| δ | 안 | 위치 중앙 | roll 중앙 | 초/스텝 |
|---|---|---|---|---|
| 0 | A 자유 풀이 (현행) | 0.0090mm | 45.80도 | 0.0027 |
| 0 | B `wrist_roll` 고정+반복 | 0.0090mm | 0.00도 | 0.0041 |
| 0 | C `q_init` 시드 스윕 9개 | 0.0090mm | 6.68도 | 0.0244 |
| 60 | B | 0.0090mm | 0.00도 | 0.0042 |
| 60 | C | 0.0090mm | 6.28도 | 0.0247 |

⚠️ **δ 섭동은 전략을 구분하지 못했다.** 예측은 "δ 가 커지면 B 의 위치가 무너진다"
였고 틀렸다. `wrist_roll` 이 위치·축과 결합이 0 이라(M5) δ 는 애초에 위치 문제를
만들지 않는다. 섭동을 잘못 골랐다 — 위치·접근축을 다양체 밖으로 밀어야 했다.
그건 S15P21A103-113 이다.

## M7. 최종 상태 — 왕복이 항등에 가까워졌다 🟢

`MujocoIK(match_roll=True)` 기본값으로 5편 x 90스텝:

| | M1 시점 | 최종 |
|---|---|---|
| 위치 오차 중앙 | 0.0088mm | 0.0088mm |
| 접근축 오차 중앙 | 0.0035도 | 0.0035도 |
| roll 잔차 중앙 / p95 | 46.98 / 82.05도 | **0.000 / 0.000도** |
| **관절각 복원 최대오차** | **126.28도** | **0.10도** |
| 미수렴 · 한계클램프 | 0/450 · 0/450 | 0/450 · 0/450 |

관절각 복원이 0.10도라는 것은 **왕복이 사실상 항등**이라는 뜻이다.
M3 의 "왕복이 관절 배치를 복원하지 않는다"는 해소됐다.

이게 층 1(변환 정확성)의 값을 크게 올린다 — 왕복이 항등이면
**하류에서 나오는 불일치는 분기 모호성이 아니라 진짜 버그다.**
