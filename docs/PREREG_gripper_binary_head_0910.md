# PREREG — 그리퍼를 회귀에서 분리한다 (이진 헤드 + BCE) · 2026-09-10

작성자: 김준태(트랙B) · 이슈 S15P21A103-34

## 질문

그리퍼 채널을 회귀 목표에서 빼고 이진 분류로 학습하면
미폐쇄 42% 와 늦은 폐쇄가 줄고 롤아웃이 배포 게이트(20%)를 넘는가.

## 착수 조건 — 이걸 먼저 본다

E1 축소판(v5 seed0 + fixed schedule, n=100) 의 **fixed 최고값**:

- **>= 30%** → 착수한다
- **< 30%** → 착수하지 않는다. 그리퍼를 완벽하게 만들어도 팔이 못 간 거리는 못 메운다.
  그 경우 병목은 팔·관측이고 이 실험은 게이트를 못 넘는다

## 지금 기준값 (오늘 트리 `65370da`, 🟢 두 실행 동일 — 결정적)

```
scripted   84/100 · 닫는 순간 중앙  4.7mm · 미폐쇄  1/100
bc v5 s0   11/100 · 닫는 순간 중앙 28.0mm · 미폐쇄 42/100 · 실패 최근접 중앙 14.3mm
```

## 무엇이 문제라고 보는가 🟡

`training_target` 의 `joint_delta_gripper_abs` 는 팔만 델타로 바꾸고 그리퍼는
절대값으로 남긴다. 그리퍼 목표는 시간상 사실상 이진이다 — 141틱 중 대부분 열림,
닫힘 전이는 1회.

**정정 (2026-09-10, 착수 전).** 초안은 손실을 MSE 로 적었다. 틀렸다 —
`configs/train/bc.yaml` 은 `loss: l1` 이다. 메커니즘이 달라진다.

**L1 의 최적해는 조건부 중앙값이다.** 그리퍼 절대 명령은 141스텝 중 약 110이 "열림"
이므로, 관측이 닫는 순간을 분해하지 못하는 구간에서 중앙값은 **항상 "열림"** 이다.
정책은 중간값에 머무는 것이 아니라 **아예 닫지 않는다.** 미폐쇄 42/100 이 그 모양이다.

그리고 이 구조는 이 저장소가 이미 한 번 겪었다. `policy/bc.py` 의 `ACTION_SPACES`
주석 🟢 2026-09-02: `joint_delta` 에서 그리퍼 **델타**가 141 중 124스텝 0 이라
L1 중앙값 0 을 배웠고, 그래서 그리퍼를 절대값으로 바꾼 것이
`joint_delta_gripper_abs` 다. **절대값도 시간상 다수결이 "열림" 이라 같은 붕괴가 한
단계 위에서 재발했다.** 오늘의 42/100 은 그 재발이다.

`target_scale` 이 채널별로 표준화하므로 **손실 크기 때문에 묻히는 것은 아니다.**
크기가 아니라 손실 **형태**의 문제다. 이 구분을 흐리지 않는다.

BCE 는 중앙값 붕괴가 없다 — 등급이 있는 확률을 맞추므로 관측이 약하게만 정보를 줘도
통과가 생긴다. 그리고 출력이 로짓 부호로 개폐를 정하므로 "명령 진폭이 문턱 미만" 으로
미폐쇄가 되는 경로가 **구조적으로** 사라진다.

## 변경

`ACTION_SPACES` 에 `joint_delta_gripper_binary` 추가.

- `training_target`: 팔 5채널 = `action - state` (**기존과 동일**),
  그리퍼 = 이진 라벨(닫힘 1 / 열림 0). 임계값은 `grasp.open_cmd`/`close_cmd` 의
  중간점을 계약 정규화 공식으로 환산해 쓴다 — 리터럴 없음
- 손실 = `L1(팔 5채널, 표준화)` + `1.0 * BCE_with_logits(그리퍼, pos_weight)`
  팔 항은 **기존과 정확히 같게 둔다.** 한 번에 하나만 바꿔야 롤아웃 차이를 귀속시킬 수 있다
- `to_action`: 그리퍼 = 로짓 > 0 이면 닫힘 명령, 아니면 열림 명령
- `target_scale` 은 그리퍼 채널을 **항등**으로 둔다 (0/1 라벨을 표준화하면
  BCE 가 보는 라벨이 0/1 이 아니게 되고 임계값이 뜻을 잃는다)

**손잡이 두 개를 착수 전에 고정한다. 튜닝하지 않는다.**

| 손잡이 | 값 | 근거 |
|---|---|---|
| 그리퍼 항 가중치 | **1.0** | 사전 고정. 결과를 보고 고르면 사후 합리화다 |
| `pos_weight` | **데이터에서 계산** (`열림수/닫힘수`) | 하이퍼파라미터가 아니라 데이터셋 통계다. 손으로 고를 것이 없다 |

## 계측기 검증 — 학습 전에 한다

세 곳(라벨 생성 · 표준화 예외 · 로짓 복호)이 서로 맞아야 동작하고 **어긋나도 예외가
나지 않는다.** 손실은 잘 떨어지고 롤아웃만 실패한다. 그래서 착수 전에 대조한다:

```
python tools/check_gripper_binary.py
```

라벨 방향(닫힘 명령 → 1), 왕복(라벨 → 명령 → 원래 명령), 그리퍼 채널 표준화 항등,
복합 손실 = `L1(팔) + 1.0*BCE(그리퍼)` 등가, `pos_weight` 없을 때 거부.
**하나라도 FAIL 이면 학습을 돌리지 않는다.**

## 사전등록 판정 (결과 확인 전 확정)

| # | 기준 | 무엇을 뜻하나 |
|---|---|---|
| 1 | **미폐쇄 <= 5/100** (세 seed 모두) | 이 변경이 직접 겨냥하는 것 |
| 2 | 닫는 순간 거리 중앙 <= 15mm | 실측 허용오차 안 |
| 3 | 롤아웃 > 20% 가 3회 중 2회 이상 | 배포 게이트 |

- 셋 다 통과 → 채택 후보. **단 5회 반복 후에 확정한다** (D-AI-30)
- 1 통과 · 3 실패 → 그리퍼는 고쳐졌고 **남은 병목은 팔**이다. 이것도 명확한 결과다
- 1 실패 → 원인은 행동 표현이 아니다. 관측이 폐쇄 시점을 담고 있지 않다는 뜻이므로
  카메라 배치·관측 설계로 넘어간다

## 예측 (실행 전에 적는다) 🟡

- 판정 1 **통과** — 이진 출력은 중간값에 머무를 수 없다
- 판정 2 **실패** — 20mm 안팎까지 개선되지만 15mm 는 못 넘는다
- 판정 3 **롤아웃 25~40%** — 게이트는 넘되 fixed schedule 의 상한에는 못 미친다

근거: 이진화는 "닫는가"를 고치지만 "어디서 닫는가"는 팔 정밀도에 묶여 있고,
v5 의 실패 최근접 중앙이 14.3mm 다. 그리퍼가 완벽해도 그 거리는 남는다.

이 예측이 크게 빗나가면(예: 롤아웃 60% 이상) 나의 실패 원인 분해가 틀린 것이고,
팔 정밀도에 대한 해석부터 다시 세워야 한다.
