## D-AI-22 · 스킬 5종 확정, 구조는 [집기=학습] + [놓기=스크립트]

작성자: 김준태(트랙B)

**결정 — 튜토리얼 스킬 5종**

⚠️ **이 다섯은 "우리가 시연할 다섯"이 아니다.** 플랫폼에 미리 학습시켜 넣어두는
   범용 프리미티브, 곧 **튜토리얼 층**이다. 시연에서 보여줄 것은 특정 페르소나를
   겨냥한 **데모 층** 스킬 1~2개이며 아직 미정이다 (페르소나 확정 대기).

   레지스트리에 `tier` 와 `status` 를 두는 이유가 이것이다. 제품 주장은
   "우리가 다섯 행동을 만들었다"가 아니라 **"사용자가 시연으로 새 행동을 추가할
   수 있다"** 이고, 그 주장을 증명하는 것은 시연 자리에서 추가된 스킬 하나다.
   다섯이 다 구현되지 않을 수 있다는 것을 전제로 둔다.

| `skill_id` | 이름 | 놓기 단계 | VLM |
|---|---|---|---|
| `pick_place` | 집어 옮기기 | 지정 좌표로 이동 후 개방 | — |
| `sort_two` | 두 곳으로 분류 | 분기된 트레이로 이동 후 개방 | 필요 |
| `align_fixture` | 지그에 정렬 | 지그 좌표로 이동, 자세 정렬 후 개방 | — |
| `present_inspect` | 검사 자세 제시 | 제시 자세로 이동, 회전, 복귀 후 개방 | — |
| `line_up` | 순서대로 늘어놓기 | 인덱스로 계산된 좌표로 이동 후 개방 | — |

**결정 — 구조**

모든 스킬은 `[집기 = 학습 정책] + [놓기 = 스크립트]` 로 분할한다.

**채택안 A** — 파지 정책 **하나**를 다섯 스킬이 공유하고 놓기 단계만 다르다.
**확장 목표 B** — 파지 정책이 게이트를 넘으면 스킬별 독립 정책 5개로 확장한다.

**왜 이 분할인가** 🟢
취향이 아니라 계측에서 나왔다. 기록된 궤적의 재생 성공률이
±5mm 4/4 · ±10mm 3/4 · ±15mm 1/4 · ±50mm 0/4 다 (2026-08-27, MuJoCo 3.12.0).
즉 물체 위치가 변하는 구간(집기)에는 정책이 필요하고, 물체가 그리퍼에 들어온
뒤(놓기)에는 필요 없다.

**왜 A 부터인가**
어느 안이든 파지 정책 **하나가 먼저 게이트를 넘어야 한다.** 하나도 못 하는데
다섯은 못 한다. 2026-09-01 기준 BC 는 롤아웃 0% 로 게이트 미통과 상태다.

**정직성 장치**
`contract/skills.py` 의 `shared_policy_report()` 가 레지스트리를 읽어
"서로 다른 학습 정책이 몇 개인가"를 항상 사실대로 출력한다. 안 A 상태에서는
"5개를 학습시켰다"가 아니라 "파지 정책 1개를 5개 작업이 공유한다"로 말하라고
스스로 경고한다. 발표에서 뒷받침할 수 없는 주장을 하지 않기 위한 것이다.

**삽입(insertion)은 제외한다.** 그리퍼 간격 1.7cm 에 ±10mm 재현 붕괴로는
공차 관리가 불가능하다. REJECTED 행.

**되돌릴 조건**
- 파지 정책이 게이트를 넘고 데이터·GPU 여유가 확인되면 B 로 확장
- 스킬마다 접근 자세가 달라 공유 정책의 성공률이 스킬별로 20%p 이상 갈리면
  그 스킬은 독립 정책으로 분리

**미검증**
- 물체를 쥔 뒤 그리퍼 안에서의 자세 편차. 정밀 배치가 필요한
  `align_fixture` 가 이 값에 의존한다. 미측정
- **데모 층 스킬이 무엇인지** — 페르소나 확정 대기. 튜토리얼 5종과 다른 동작일 수 있다
- 다섯 중 몇 개가 실제로 게이트를 넘을지. `status` 필드가 항상 사실대로 말한다

## D-AI-23 · 스킬 레지스트리는 게이트 없는 정책을 거부한다

작성자: 김준태(트랙B)

**결정**
레지스트리 항목의 `policy.gate` 는 **필수 필드**다. 없으면 배포 불가로 판정한다.
게이트 기록은 다음을 모두 만족해야 한다.

```
metric == "rollout_success"
n     >= 100      값 자체가 아니라 판정 가능성의 조건이다
runs  >= 3        학습 간 분산이 25%p 라 단일 실행은 체크포인트를 대표하지 못한다
value  > 0.20
ci95[0] > 0.20    신뢰구간 하한도 게이트 위여야 "통과"다
```

**왜**
게이트가 선택 필드이면 "학습이 끝났다"가 조용히 "된다"로 바뀐다.
`n >= 100` 과 `runs >= 3` 은 2026-09-01 실측에서 나왔다 — n=20 의 CI 반폭이
±18%p 로 게이트 폭과 같았고, 동일 데이터·설정의 학습 2회가 25%p 갈렸다.

**되돌릴 조건**
없다. 완화 제안이 나오면 게이트를 낮추는 대신 n 을 올리는 쪽을 먼저 검토한다.
게이트 변경은 사후 합리화, n 증가는 정밀도 개선이다.

## D-AI-24 · VLM 출력은 enum 제약 + 기권 게이트

작성자: 김준태(트랙B)

**결정**

```json
{
  "skill_id": "pick_place | sort_two | align_fixture | present_inspect | line_up",
  "target": {"description_ko": "...", "bbox_norm": [x0, y0, x1, y1]},
  "destination": "left_tray | right_tray | fixture | origin | target_pose | null",
  "confidence": 0.0,
  "abstain": false
}
```

- `skill_id` 와 `destination` 은 **constrained decoding** 대상이다. 자유 생성 금지
- 스킬마다 허용 `destination` 이 다르다 (`CATALOG` 가 정본)
- **`confidence < 0.70` 이거나 `abstain` 이면 팔을 움직이지 않고 사용자에게 되묻는다**

**왜 제약하는가**
자유 생성 모델은 그럴듯한 여섯 번째 스킬 이름을 만들어낸다. 하류에서 조용히
빠져나가는 `if` 문이 붙으면, UI 는 동작 중이라고 표시하는데 로봇은 아무것도 하지
않는 상태가 된다. `parse_vlm_decision()` 은 enum 밖의 값에 예외를 던진다.

**되돌릴 조건**
`0.70` 은 🟡 잠정값이다. M0(파인튜닝 없는 베이스 모델의 스킬 선택 정확도, n=100)
측정 후 재조정하되, **재조정했다는 사실과 이유를 반드시 기록에 남긴다.**

## D-AI-25 · 스킬을 튜토리얼 층과 데모 층으로 나눈다

작성자: 김준태(트랙B)

**결정**

| 층 | 무엇 | 개수 | 상태 |
|---|---|---|---|
| `tutorial` | 플랫폼 기본 제공 범용 프리미티브 | 5 | 전부 `planned` |
| `demo` | 특정 페르소나 겨냥, 시연에서 추가해 보이는 동작 | 1~2 | **미정 — 페르소나 확정 대기** |

레지스트리 항목은 `tier` 와 `status`(`planned`/`collecting`/`training`/
`gate_failed`/`deployed`)를 반드시 갖는다. `demo` 층은 `notes.persona` 가 없으면
검증에 실패한다 — 누구를 겨냥한 동작인지 없이는 시연에 쓸 수 없다.

**왜**
"5개를 학습시킨다"는 계획이고 다 구현되지 않을 수 있다. 계획된 개수를 구현된
개수처럼 말하는 것을 막아야 한다. `shared_policy_report()` 가
`실제로 동작하는 스킬은 N개다` 를 항상 출력한다.

더 중요한 것은 제품 주장의 위치다. 튜토리얼 다섯이 동작하는 것보다 **시연 자리에서
하나가 추가되어 동작하는 것**이 "사용자가 새 작업을 추가할 수 있다"는 주장의 더
강한 근거다.

**되돌릴 조건**
페르소나가 확정되어 데모 스킬이 튜토리얼 5종 중 하나와 같아지면 층 구분을 없애고
단일 목록으로 되돌린다.

**미확정 — 결정 필요**
페르소나. D-AI-19 에서 도메인(다품종 소량생산 소형부품)까지는 좁혔지만
"누가 쓰는가"는 아직 없다. 데모 스킬은 여기에 종속된다.
