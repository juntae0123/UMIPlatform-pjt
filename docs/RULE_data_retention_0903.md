## 전제가 오늘 바뀌었다

렌더가 결정적이 됐다 (`cameras.offsamples: 0`, L37 해소 🟢).
그래서 **시뮬 데이터셋은 재생성 가능한 자산이 됐다.**
같은 `seed` + 같은 `git rev` + 같은 `config_sha` 면 비트 단위로 같은 npz 가 나온다.

이전에는 MSAA 때문에 재수집이 다른 픽셀을 냈으므로 데이터를 지우면 그 실험이 재현
불가능했다. 지금은 아니다. **지워도 되는 것과 안 되는 것의 경계가 옮겨졌다.**

## 규모 추정 🟡

| | 계산 | 용량 |

| 현재 시뮬 데이터셋 3종 (v1·v2·v3) | 885 + 886 + 796 MB | **약 2.6GB** |
| 5스킬 × 150편 본수집 | 750편 × 8.13MB | **약 6.1GB** |
| 스킬별 학습 3회 체크포인트 | 5 × 3 × 2 × 5MB | 150MB |
| UMI 실데이터 5스킬 × 150편 | 750편 × 8MB 추정 | 약 6GB (**삭제 불가**) |

시뮬 쪽 12GB 이상이 전부 재생성 가능하고, 실데이터 6GB 는 전부 보관 필수다.
**용량 압박은 지울 수 없는 쪽에서 오지 않는다.**

## 절차

지우기 전에 항상: **무엇을 지울지 보이고 검토받는다** (프로젝트 규칙).

```bash
# [서버] 1. 현황 확인
du -sh datasets/* checkpoints/bc out/* 2>/dev/null | sort -h

# [서버] 2. dataset.json 은 저장소로 (npz 없이)
git add -f datasets/*/dataset.json && git status --short datasets/

# [서버] 3. EXP_LOG 를 저장소로 — 이게 증거 인덱스다
git add AI/EXP_LOG.jsonl

# [서버] 4. 지울 목록을 먼저 출력 (지우지 않는다)
ls -la datasets/sim_pick_v1 | head -3 && du -sh datasets/sim_pick_v1
```

## 미구현 — 재생성 검증기

C 등급을 실제로 지우려면 **"지운 뒤 정말 복원되는가"를 먼저 증명해야 한다.**
지금 그 검증기가 없다. 없는 상태에서 지우면 "재생성 가능하다"는 주장이 미검증이다.

필요한 것: `tools/verify_regen.py` — `dataset.json` 의 seed·config_sha·git rev 로 재수집한
뒤 원본과 npz 해시를 대조한다. 통과하면 원본 삭제 승인, 실패하면 삭제 금지.

**그 검증기가 나오기 전까지 시뮬 데이터셋을 지우지 않는다.** 오늘 시점 결정.
