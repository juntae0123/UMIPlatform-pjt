## 2. 네가 채울 칸 — 시그니처는 이미 박혀 있다

```python
def to_raw(
    *,
    pose_log: Path,           # ARCore pose 스트림. 형식 미정
    frames: Path,             # RGB. 원해상도 HWC uint8 그대로 (줄이는 건 변환기 일)
    recording_id: str,
    skill_id: str,            # contract.ids.SKILL_IDS 중 하나
    calibration_id: str,      # 빈 값이면 실기록이 거부된다
    t_phone_to_pinch: np.ndarray,   # (4,4) 이슈 28 · L30 미실측
    t_world_to_base: np.ndarray,    # (4,4) 이슈 29 미실측
) -> RawEpisode
```

**미실측 변환을 필수 인자로 뒀다.** 값이 없으면 호출 자체가 안 된다.
기본값을 주면 조용히 통과하고 그 근사값이 정본이 된다.

지킬 것 4개:

1. `pose_timestamp` 와 `image_timestamp[cam]` 을 **따로** 채운다. **길이가 달라도 된다.**
   같게 맞추면 동기화를 이미 했다고 스키마가 가정하는 것이다
2. `eef_quat` 규약: `R[:,2]` = 손가락 방향(접근축), `R[:,0]` = 턱 열리는 방향
3. `gripper_gap_m` 은 **미터**. `configs/so101.yaml` 의 `gap_curve` 는 **cm** 다
4. 저장은 `umi.raw.write_raw`. 스키마 위반이면 저장되지 않는다

## 4. 대행 중 내린 결정 2건 — 되돌릴 조건 포함

전문은 `docs/DECISIONS_0907_draft.md`.

**D-AI-30 — 변환기를 `AI/umi/` 신설 패키지에 둔다**

- `track_a/convert/` 가 아닌 이유: raw 스키마는 양 트랙이 읽어야 하는데 거기 있으면
  트랙 B 가 "`track_a/` 를 임포트하지 않는다" 규칙을 깨야 한다
- 대가: 트랙 간 접점이 `contract/` 하나에서 `contract/` + `umi/` 둘로 늘었다
- **되돌릴 조건**: 스키마를 `track_a/` 로 옮기는 게 낫다고 판단되면 뒤집는다.
  단 **트랙 B 가 `track_a/` 를 임포트하지 않는 방법이 함께 제시돼야 한다**

**D-AI-31 — UMI pose 의 roll 을 버리지 않고 맞춘다**

- 최초 초안은 정반대였다: *"5자유도로는 roll 을 못 내니 버리고 잔차만 보고한다."*
  **실측이 뒤집었다** — `wrist_roll` 은 위치·접근축과 결합이 0 이다 (M5)
- **되돌릴 조건 둘 중 하나면 무효**:
  (a) 그리퍼 형상 변경으로 파지점이 roll 축을 벗어나면 (로봇팔 변형 예정)
  (b) 실물 `wrist_roll` 가동 범위가 MJCF(`[-2.744, 2.841]`)보다 좁으면

## 5. 실측된 수집 프로토콜 제약 🟢

`MEASURE_umi_reach_0907.md`.

| | 수용률 90% 이상 허용폭 |
|---|---|
| **접근 방향** | **약 5도** (10도에서 20.5% 로 붕괴) |
| 위치 | 약 20mm |

**시연자의 접근 방향이 위치보다 훨씬 중요하다.** 기전은 관절 한계 — 같은 위치에서
팔을 기울이려면 손목이 범위를 넘어간다.

기존 규칙 "환경은 다양하게, 시연 방식은 동일하게"에 숫자가 붙었다.
**일정해야 하는 것은 주로 각도다.**

⚠️ 위치 20mm 는 **IK 기준**이다. 재생 허용오차는 ±10mm 에서 3/4 🟢 이므로
   **위치 예산을 지배하는 것은 IK 가 아니라 재생이다.** 두 값을 섞지 마라.

## 7. 이 파일들의 이전 서술을 믿지 마라 — 2026-09-08 정정

대행 중 실측으로 **틀린 것이 판명돼 고쳤다.** 캐시나 옛 브랜치에서 이전 내용을
보게 되면 아래가 정정판이다.

| 파일 | 이전 서술 | 실측 |
|---|---|---|
| `track_a/pose/__init__.py` | "위치 3 + 접근축 2 = 정확히 5구속. **6자유도 완전 자세 제어는 불가능**" | **틀림.** 4관절이 위치+축, `wrist_roll` 이 roll 전담·완전 독립. roll 은 재현 가능하다 |
| `track_a/convert/__init__.py` | "여기서 `contract.episode` 를 직접 임포트해 `Episode` 를 만들라" | **더 이상 아님.** `umi.raw.RawEpisode` 를 만든다 (D-AI-30) |
| `track_a/sync/__init__.py` | 계약 검증기가 10ms 로 검사한다 | 맞지만 **그 게이트는 pose↔이미지 오차를 못 본다.** 둘 다 pose 스트림에서 나온다 |
| `sim/mujoco/kinematics.py` | "접근축 둘레 회전은 나머지 다섯과 **독립적으로 고를 수 없다**" | **틀림.** 코드 동작은 정상, 설명만 다르다. 시뮬·정책 대화에 전달했고 그 파일은 안 고쳤다 |

## 10. 이 대행의 한계 — 솔직히

**계약 경계 결정에 검토자가 없었다.** 한 사람 판단이 그대로 통과했다.
완화는 사람이 아니라 계측으로 했다 — 결정마다 "이게 틀렸으면 무엇이 어떻게
보이는가"를 재는 검증을 붙였고, 실제로 D-AI-31 초안을 뒤집은 것은 사람이 아니라
계측이었다.

그래도 **네가 뒤집을 여지를 남겨뒀다.** 되돌릴 조건이 D-AI 마다 붙어 있고,
틀린 것으로 판명된 서술은 정정 이력과 함께 남겼다. 동의하지 않는 결정이 있으면
그것도 기록 대상이다.
